# Agent 移动界面改造计划 · 2026-11-07

状态：N0–N5 已实现并按部分提交，设备采样与剩余验收边界见 [实施记录](agent-mobile-implementation-2026-11-07.md)。依据 [本轮评估](agent-mobile-design-audit-2026-11-07.md)；N0–N5 是新一轮改造编号，不替代或重新打开已完成的 M1–M5 功能清单。

## 1. 目标与范围

目标体验：用户在手机上始终知道当前项目、助手正在做什么、哪些内容需要自己决定，以及下一步能去哪里。界面把创作内容、待处理事项和成果放在前面，把配置、原始记录与技术标识放在需要核验时展开。

沿用浅色/绿色主题、Material 图标、四个主入口和现有对象身份。主要调整助手会话、技能目录/详情/选用、运行历史/详情、生成审阅与创作结果摘要。项目计划、候选采用等共享表面只调整本轮涉及的展示与回流，不顺带重建全产品信息架构。

已有单次技能、安装与提炼、版本快照、分别授权、请求去重、任务查询和候选采用能力继续复用。界面改造不复制运行时、授权服务和领域状态机。默认不需要数据库迁移；若排查证明必须修改存储，单独开切片并补迁移与恢复证据。

## 2. 页面与表面的最终分工

| 表面 | 目标结构 | 主动作与退出 |
|---|---|---|
| 助手会话 | 顶部项目；会话入口、任务入口、更多；对话与本轮成果；上下文摘要；输入 | 编辑态发送，运行态停止本轮；历史与新建收进会话入口 |
| 下次消息技能 | 底部选择抽屉：继承/仅内置、搜索、选项、已选摘要 | 确认用于下次消息；关闭不写入，返回输入焦点 |
| 技能管理 | 手机全屏：标题、明确范围、搜索、分类、紧凑能力列表 | 添加/进入详情；返回原来源并保留目录状态 |
| 技能详情 | 手机全屏：用途、输入、输出、适用范围；版本来源；原始文件折叠 | 本地技能按能力允许选择或管理默认；内置只读、按需发现，不伪造可选择开关 |
| 运行记录列表 | 标题随范围变化；明确范围选择；时间、会话、状态列表 | 点击运行；空态只描述当前查询覆盖的记录 |
| 运行详情 | 标准顶栏；结果/状态；关联对象与待处理；执行阶段；本轮消息；诊断 | 回到相关会话/对象；刷新为顶栏辅助动作 |
| 核对生成请求 | 手机全屏：本次对象、服务账号、发送内容与素材、规格、次数费用；技术证据逐层展开 | 分别勾选外发与消费后确认；取消返回原草稿/计划 |
| 创作结果摘要 | 对象名称/缩略图、事实状态、当前下一步 | 待提议审阅、核对请求、查看任务、审阅候选随真实状态出现 |

项目选择保留在标题区域；会话选择抽屉里集中提供新建与历史，避免“新建会话、历史、任务、更多”四个并列图标压缩项目名。任务入口保留，防止用户停止助手后找不到仍在进行的生成任务。窄屏不足时由明确的会话按钮承载会话菜单，不继续缩小点击区域。

顶部只放导航与低频入口；主要决策靠近正在阅读的对象；输入附近只放影响下一条消息的上下文。内置技能「可发现」与本地技能「选用」保持区分。项目默认、单次覆盖、全局启停不能用一个含糊的“启用”按钮承载。

## 3. 分阶段排程

建议按 10 个可独立审查和回退的切片实施，不一次替换整个助手页面。

| 阶段/切片 | 改造结果 | 主要文件/对象 | 依赖 | 完成门槛 |
|---|---|---|---|---|
| N0a 入口排查 | 查明 QA 项目读取失败来自业务、数据、包装层还是 native/JS 组合 | AgentWorkspace、databaseClient、QA 入口与构建身份 | 无 | 保留原错误链；当前源码与匹配 native 包取得正常会话；或准确定位尚存阻塞 |
| N0b 恢复与基线 | 错误有恢复出口，正常/运行/失败/待审阅截图齐备 | AgentWorkspace、AgentScreen、既有恢复页 | N0a 的诊断分类 | 重试/返回/只读历史或恢复入口与故障类型匹配；不清输入、不隐式换项目 |
| N1a 技能目录 | 范围、搜索、分类和能力列表优先，减少重复说明 | SkillLibraryScreen、builtinCatalog | 本轮目录截图足够启动，不依赖会话修复 | 目标设备上首项能力出现在内容区上半部；作用范围明确；停用后果在相应操作前可见 |
| N1b 技能详情与回流 | 用途详情全屏，中文优先，原文可核验；会话不再被管理面板上下分割 | SkillLibraryScreen、AgentScreen、PromptAssistantUi、SkillQuickPicker | N1a；会话回流依赖 N0 | 搜索/筛选/滚动、输入/附件、未保存单次选择均能返回恢复 |
| N2a 运行列表 | 全部/项目/会话范围和空态准确 | 当前 history intent、SkillLibraryScreen、运行记录查询 | 本轮历史截图足够启动 | 当前范围准确；筛选分页和深链有效；记录覆盖边界清楚 |
| N2b 运行详情 | 结果先于操作；辅助动作降权；消息角色与时间本地化 | SkillRunScreen、ReadOnlyMessage、既有活动摘要 | N2a，结果关联复用既有查询 | 首屏先读到事实状态；原始证据仍可查；打开和刷新均不执行任务 |
| N3 会话与输入 | 精简顶栏、上下文按状态展开，短选择/长管理各归其层 | PromptAssistantUi、AgentScreen、AssistantActions、AgentCreativePanel | N0、N1b | 窄屏/键盘下发送和停止可达；不丢草稿/引用；失效范围与阻塞不能折叠隐藏 |
| N4a 生成审阅 | 决策信息前置、素材人可读、技术证据分层 | GenerationRequestReview、共享单次/计划/批次审阅组件 | N0 正常审批基线；N3 回流约定 | 明确发送内容与未知费用；分别授权；修订/账号变化需重新核对；取消不提交 |
| N4b 创作状态衔接 | 对话内摘要准确导向提议、请求、任务或候选 | AgentCreativeCards、ActivityGroup、既有任务/候选入口 | N2b、N4a | 停止助手不误报取消任务；未知结果导向查询；候选与采用有明确界限 |
| N5 视觉与设备收尾 | 本轮相关组件统一触控、字号、间距、图标和读屏状态 | theme、会话/技能/运行组件、设计目录 | 各已完成切片 | 同状态前后对照、设备矩阵与回归通过，证据覆盖独立标注 |

执行主线：N0 → N1 → N2 → N3 → N4 → N5。若 N0 仍受环境问题阻塞，N1a 与 N2 的目录/只读详情整理可继续；N3/N4 的布局与完整回流验收必须等待真实可运行基线。没有正常截图时不宣布正常会话“改造完成”。

## 4. 各阶段具体设计决策

### N0：把入口故障和界面改造拆开

保留底层异常分类与可复制的脱敏诊断，不再只吞掉错误后显示一句通用失败。先用匹配当前源码的 native 构建复现，再对照 QA 包，避免用旧 native 壳的表现直接修改生产逻辑。

错误展示按可执行恢复动作划分：临时读取失败→重试；模型未配置→连接设置并返回；项目不存在/已归档→解释原范围并允许明确选项目；数据库保护/恢复→已有恢复路径。仅当存储与项目范围可信时开放本地历史。草稿维持其原 thread/project 归属，不因错误自动跳到另一个项目。

### N1：技能目录、详情、选用分工

目录首屏删除重复的权限与可发现说明，将必要边界放在范围说明、选择确认或停用确认处。行内使用名称、两行以内用途、来源/状态，点击进入详情；安装/启停不与展开原文混在同一触点。

`builtinCatalog` 增加用于展示的中文长说明解析，优先取已有 `desc-cn`。若缺少结构化输入/输出字段，仅使用经核实的现有描述或整理过的本地文案，不由 UI 随意推断能力。保持 `builtinSkillSnapshot` 的执行字段不变，不因展示本地化改变历史快照含义。

详情优先复用现有 agent-skills 路由内的独立 detail 表面，以稳定技能路径/版本 ID 寻址，避免把 SKILL.md 正文塞进 URL。若现有容器无法满足深链、冷启动返回或无障碍焦点，才新增明确详情路由并登记设计目录。默认策略必须在 N1b 实施时形成 ADR。

来自快速选择的管理跳转携带 `returnThreadId`、项目范围和来源身份；未确认的选择草稿保留在发起表面或现有草稿层，不能在导航时提前写入单次选择。系统返回、标题返回和关闭按钮使用同一退出规则。

### N2：让运行记录回答“发生了什么”

将运行历史列表/详情的展示从庞大的技能管理页面拆成专用组件，兼容现有 `intent=history` 链接。先核对 `store.runs` 的真实覆盖范围：如果只覆盖带技能证据的运行，就明确标注；若要展示所有会话运行，以已有会话持久化记录作为事实来源，并允许无技能快照的运行出现。不能为了凑列表补造技能证据；两种存储合并若超出展示改造则单独拆工程任务。

详情顶栏采用返回箭头、短标题、刷新。正文先说「助手回复已完成/已停止/失败」，有事实记录时再显示关联对象与结果。没有工具阶段就直接引导本轮消息，不用“工具 0 次”当主要结果。技术 ID、调用统计与原始工具信息放诊断里；缺少历史快照时继续诚实说明。

### N3：先读对话，再处理上下文

默认输入附近显示可展开摘要，例如「当前镜头：灯塔远景 · 技能：项目默认」。失效选择、不可用项目或待核对版本独立显示为可操作阻塞，不受一行摘要截断影响。长镜头名允许在详情完整查看；不能用隐藏上下文换首屏干净。

下次消息选择保留现有抽屉；管理技能全屏；长输入沿用已有全屏编辑能力。来自编辑器、附件引用、版本预览或设置的返回恢复同一草稿、选择位置与附件身份。键盘弹起时输入框与发送/停止保持可达，底部导航沿用现有可见性规则并实测，不直接改全局壳层。

### N4：决策与证据分层，状态必须精确

生成核对第一页优先让用户理解：哪个项目/镜头，哪个服务和账号，发送哪些文字与素材，图片张数/视频规格，请求几次，费用是否可知。账号名称未经服务验证时明确按绑定显示，不伪造服务商身份；素材名称和预览仍绑定确切版本，名称相同也不能混用。

规格可分组；完整 JSON、绑定 ID、凭据版本、版本指纹作为证据展开。费用未知、无金额上限、请求次数与有效期始终明确可见。外发与消费分别勾选，确认前不写授权。确认区保持可达；若现有合同要求展示全部纳入请求，必须满足后再允许确认，不能因为固定底栏而绕过。

批次仍展示实际包含/排除集合，文案与提交集合一致。确认时继续核对修订、范围、固定版本和账号；任何相关变化重新核对并重置确认状态。网络结果未知给“查询原任务”，确定失败才允许明确新尝试。

| 事实对象/状态 | 用户看到的推荐动作 | 不能暗示的结果 |
|---|---|---|
| 待审阅提议 | 审阅修改 | 已应用、已生成 |
| 版本冲突提议 | 核对差异 | 自动覆盖当前版本 |
| 已应用的文字修改 | 查看修改；有草稿时进入核对请求 | 已授权消费 |
| 待确认生成草稿 | 核对生成请求 | 已提交 |
| 已提交生成任务 | 查看任务进度 | 助手停止即任务取消 |
| 结果未知 | 查询原任务 | 点击查询会重新生成 |
| 生成候选 | 审阅候选 | 已采用 |
| 已采用版本 | 查看当前采用版本 | 保存到手机已完成 |

这些是展示映射，状态与计数始终读取既有记录，不维护另一份 UI 执行状态。

### N5：沿用品牌，收拢组件

间距沿用项目 4dp 尺度；页面边距使用既有自适应 helper；正文建议 15–16sp，关键辅助信息不低于 12sp，允许系统字体放大；目标点击范围至少 48×48dp。圆角按现有控件角色统一，不给每个行项新增边框和底色。

只把发送、生成确认或当前待处理动作作为对应任务的主要强调；停止、失败和授权等语义允许独立表达。保留 Material 系列，星光替换为技能/文件语义图标；「FINAL H3 PROMPT」改为「H3 提示词 · 定稿」，草稿则明确标为草稿，不推断“最新”。明确区分规范化展示与领域语义，不能仅为文案短而合并状态。

## 5. 返回与草稿合同

| 进入路径 | 关闭/返回后恢复 | 允许写入的时机 |
|---|---|---|
| 会话→下次技能 | 输入内容、附件、选区、原会话 | 点击“用于下次消息” |
| 下次技能→管理→目录/详情 | 未确认选择、搜索与原范围 | 仅明确默认管理或确认单次选择 |
| 目录→技能详情 | 分类、搜索、滚动与选中对象 | 查看详情不写启用/授权 |
| 会话→运行历史→详情 | 原筛选、分页、滚动；回会话恢复消息位置 | 查看/刷新不重跑 |
| 草稿/计划→核对请求→取消 | 原对象、版本、输入与来源 | 最终分别确认后提交 |
| 核对请求→补配置→返回 | 同一草稿，重新 prepare 并核对新账号/规格 | 保存配置本身不提交 |
| 任务→候选审阅→返回 | 原任务与候选版本 | 明确采用才改变采用记录 |

路由仅传身份与必要来源参数，不传附件正文/技能文件/授权快照。冷深链缺少来源栈时返回稳定工作区，按来源类型明确回退；不能把所有页面都硬编码返回项目页。

## 6. 每个切片的交付与测试

1. 先给出当前状态、目标顺序、状态动作与返回合同；本轮保持既有品牌和组件，不另起视觉方向选型。
2. 最小实现并复用领域服务；一片完成后立即核对同版本同状态截图。
3. 对有行为变化的范围执行相关回归和类型检查：技能范围/未保存导航、历史分页与准确旧版本、请求修订/去重/许可、返回后草稿与附件。纯文字/间距改动以视觉和无障碍检查为主，不新增镜像实现的测试。
4. 页面/表面或点击关系变化时更新 page-catalog、target-and-flows 和对应 ADR，运行目录及来源校验。保持“已实现”“设备采样”“真实服务验证”分开记录。
5. 按切片提交，可独立回退展示变化；共享组件只改本轮相关角色，避免一次影响全部项目/任务页面。

设备验收先每片跑 412dp/字体1.0，再在会话、技能详情与生成审阅这些关键表面做 360dp/412dp、字体1.3/2.0、更大窗口的重排；跨键盘、系统返回/预测性返回、切后台与恢复。TalkBack 核对焦点顺序、选中/展开/禁用、错误播报和回到来源焦点。返回路径在变更切片中验收，不全部拖到 N5。

主链至少跑通：输入并加附件→下次技能→管理往返→确认→发送；提议→审阅→核对生成→取消/确认→任务→候选→明确采用。对真实模型/供应商路径只按获得的实际证据标记；离线 fixture 不能代替真实媒体与消费链验证。

## 7. 验收指标与完成定义

- 目录同设备首项能力从约366dp前移到内容区上半部，且没有通过缩小字号和点击区实现。
- 运行详情第一屏优先呈现事实状态及可用结果；返回/刷新不占用全宽按钮区。
- 从技能、设置、历史与审阅取消返回，草稿/附件/作用范围丢失为零；错误项目写入和意外提交为零。
- 全部/项目/会话的标题、筛选、空态与真实查询覆盖一致；缺少技能快照不伪造。
- 360dp、大字体与键盘下主要动作可达，文本允许重排，关键错误不被截断。
- 各片都有来源提交/构建身份、同状态对照与精确覆盖声明。历史测试通过数字不作为本轮验收结果。

本轮交付已包含 N0–N5 实现。实现完成、离线设备采样和真实供应商验收分别记录；完整真实媒体消费链及辅助技术全矩阵不因本轮截图通过而标记完成。
