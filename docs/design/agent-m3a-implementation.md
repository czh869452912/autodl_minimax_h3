# M3a：建议与草稿审阅

日期：2026-11-04。基于已提交 M1/M2 `e6fc2dff` 继续；对应评估 27–30、32 及 50 中的待处理/已记录区分。完整 M3、活动诊断和请求授权仍按阶段计划推进。使用现有 Android 主题、数据库与路由。

## 当前任务合同

会话“本轮创作” → 具名对象卡 → 审阅具体修改 → 采用或拒绝 → 返回原会话查看实际结果。空草稿 → 完善这份草稿 → 原固定草稿编辑器；保存草稿与提交生成有明确区别。

| 对象状态 | 展示与下一步 | 写入边界 |
| --- | --- | --- |
| 待审阅修改 | 项目/镜头名称、变更字段数与字段名；待处理优先 | 打开卡片不写入 |
| 展开审阅 | 只列实际变化的字段，原内容与建议逐项对照；长文本可展开 | 采用复用 `change.resolve` 的版本事务；拒绝不改目标内容 |
| 修订冲突/目标不可用 | 明确原因；有当前对象时显示原/当前/建议三方对照 | 隐藏采用，保留拒绝；不自动合并或覆盖当前版本 |
| 已采用/已拒绝 | 持久化终态、处理时间、只读对照及“查看修改结果” | 不再显示决策按钮；同轮卡片保留固定建议身份 |
| 编辑中草稿 | 类型、规格、尚未提交、描述或缺口、完善入口 | 空描述只引导完善；非空描述保留既有请求核对流程 |

采用修改只更新项目或镜头的文字/状态，不等于生成许可。摘要按领域事实区分待审阅、待完善草稿、任务和候选，不另存一套展示状态。提议终态可在原运行的成果读取中继续定位；项目活动列表暂留本次刚处理的建议，避免点完立即消失。

`proposalPresentation` 负责字段和状态展示，以及当前版本的只读比较；`ProposalReviewCard` 负责审阅呈现；`ProjectActivityPanel` 负责精确项目/建议读取、并发操作锁、写后重读及过期读取隔离。冲突预读不是最终写入依据，用户审阅后再发生修改仍由领域事务拒绝。跨项目建议不得被固定链接读取或处理。

## 验证

类型检查通过；9 套相关测试共 58 项通过。新增真实 SQLite 集成覆盖：仅显示变更字段、实际采用终态/时间、重复点击仅处理一次、预存冲突、审阅后发生冲突、拒绝保留当前内容、列表终态保留、跨项目固定链接隔离及零生成任务。既有会话/工作区、建议服务、对象定位与卡片回归同时通过。

Android 隔离样本完成项目简报采用、镜头描述采用、另一镜头拒绝、修订冲突三方对照、原会话摘要数量更新、终态回访与空图片草稿编辑。字体 2.0 样本检查冲突内容及拒绝操作可滚动到达；最终包再次检查摘要、卡片、冲突和草稿入口。详见 [版本、截图与数据回读](evidence/2026-11-04-m3-review/README.md) 及 [前后对照](evidence/2026-11-04-m3-review/comparison.png)。

设备采用既有 x86_64 debug 原生壳、当轮新导出的 Hermes bundle、对齐签名后安装；本轮没有重新运行 Gradle 或生成发布包。样本只使用本机合成数据、无响应的回环模型配置；没有发送消息、调用模型或生成供应商。数据库回读为两项采用、一项拒绝、一项冲突待审阅；该项目生成任务、授权、外发许可及额度预留均为零。
