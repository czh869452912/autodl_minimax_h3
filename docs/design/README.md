# 页面与交互设计谱系

基线：2026-11-01，源码 `56f16751` / beta.47。维护对象是 Android APK；**桌面执行端、远端 Worker 均为禁止项**。桌面和网页竞品只作为交互参考。

## 从哪里看

1. [研究与来源对照](research.md)：行业维护方式、竞品可借鉴之处及证据边界。
2. [现状地图与逐页审查](page-review.md)：自动生成的全部路由、重要子表面、问题与建议。
3. [目标架构与交互合同](target-and-flows.md)：建议的归属、主流程、状态和返回规则；**属于提案，尚未实施**。
4. [本轮截图与步骤](evidence/2026-11-01/README.md)：实际采样与未覆盖范围。
5. [设计决策及迁移谱系](decisions/0001-page-design-lineage.md)：为什么这样改、替代方案、旧入口如何演进。

`page-catalog.json` 是页面清单和逐页建议的结构化来源。`page-review.md` 是它的生成视图，避免维护两套清单。流程与决策使用 Markdown + Mermaid；截图与版本一起保留。这样延续现有仓库工作方式，无需另建付费设计平台。

## “谱系”的含义

谱系同时回答六个问题：有什么页面；归谁管理；用户为完成什么任务到这里；这里有哪些状态；完成/取消/系统返回去哪里；本次为什么从旧设计变为新设计。**文件目录、视觉层级、点击图、任务流程不是同一棵树。** `parent` 只表示信息归属，不能当作返回实现。

本轮调研未发现唯一强制的“页面树设计谱系”格式。这里采用行业已有的页面清单、信息架构图、任务流、状态规格、设计历史和决策记录的组合；JSON 字段和校验脚本是本项目约定，不声称是行业认证标准。出处见 research.md。

## 审查结论

当前方向应是保留已有能力和四个主入口，重组页面职责与任务流程。不要以隐藏所有按钮为目标：高频下一步必须明显，低频工具随对象和状态出现。目录覆盖 **29 个路由页面、2 个壳层、26 个重要非路由表面、48 条关键点击关系**；这是源码覆盖，设备截图仅覆盖证据报告列出的状态。

| 优先级 | 页面族 | 核心问题 | 建议 |
| --- | --- | --- | --- |
| A | 项目概览、镜头 | 概览承担工具目录；每张镜头卡重复多条制作路径 | 概览显示进度与下一步；列表显示缩略图、状态和推荐动作，制作进入镜头工作区 |
| B | 技能、助手 | 浏览、选用、安装、编辑、历史混在同一目录 | 输入旁快速选用；管理、添加、提炼分任务；运行历史归助手 |
| C | 能力、连接、设置 | 用户需要拼接“账号、模型、工作流、输入能力”的关系 | 按用途显示就绪性；缺口直达所需配置，再回原请求 |
| D | 素材、设定、检查 | 技术工具与内容管理缺乏对象中心；设定空态直接展开编辑 | 资料目录先浏览对象；选中具体版本后处理、检查、绑定 |
| E | 时间线、交付 | 参数、工程、合成、导出同页展开，作品关系不直观 | 预览与片段轨优先；选中编辑；工程和导出分层 |

A–E 是建议实施顺序，不是缺陷严重性。当前内置技能已能在目录发现；现存问题是展示密度、使用入口和多任务混合，不继续沿用“内置技能不可见”的旧结论。素材选择器已有目标提示、空态恢复和确认采用，应该保留并统一其角色用语。

## 持续维护

每个修改页面或导航的切片同时更新以下内容，避免先实现功能、最后补一排入口：

- 给新页面/弹层分配稳定 ID；更名不改 ID，拆分/合并记录 `replaces` / `replacedBy`，不删除历史证据。
- 写清用户任务、所属范围、当前状态的主操作、次操作、危险操作、入口和回流、异常状态及源码位置。
- 在目录中区分 `route`、`surface`、`shell`；短时选择、工具抽屉也要登记，不滥增路由。
- 更新相关任务流和设计决策，附同版本设备截图；未采样的状态明确写“待设备验证”。
- 运行 `node scripts/design/check-page-catalog.mjs`；修改目录后运行 `node scripts/design/check-page-catalog.mjs --write` 生成逐页报告，再运行无参数检查。
- 运行 `node scripts/design/check-page-catalog.mjs --check-sources` 核对已审查的 64 个关键源文件是否漂移。默认检查仅警告源码变化，严格模式报错。审查变更、更新对应页面/边和证据后，才能将 `sourceDigests` 更新为这些文件原始字节的 SHA-256；生成报告不会自动刷新基线。
- 本脚本校验路由覆盖、ID、父关系、文件存在、证据引用和生成文档一致性；**不证明交互可用，不自动验证所有运行时跳转**。尚未接入 CI，合入流程应增加上述命令。

职责按角色而非假定人员分配：设计负责人维护任务、状态和架构；实现者维护路由与行为；审查者核对来源、截图与回流。角色可以由同一个人承担，但功能测试通过不能代替交互验收。

## 状态与验收

目录的现状是源码审查基线；建议统一标为 proposed。只有达到以下条件才能标为 implemented / device-verified：页面任务与目标一致，旧入口兼容，关键状态覆盖，正向与返回链均实际完成，截图的版本/数据条件可复现。截图更新不得覆盖旧版本。

优先验证五条完整任务：首次准备并生成；项目镜头制作并采用；助手提议并经授权执行；选用/添加技能并回到原会话；连接补全后回到原请求。不要以“20 个按钮均可点”作为成功标准。

本目录作为后续页面设计的现行入口。`docs/reviews/` 和既有设计文档保留为历史依据；若规格冲突，应新增决策解释取舍，而不是把旧审查结论全部当作当前缺陷。
