# D002：将会话技能选用与技能管理分开

状态：M1 已实现，设备覆盖以证据报告为准。日期：2026-11-04。承接 D001 的技能快速层归属，未替代其他页面族的提案。

## 问题与决定

用户为下一条消息选技能时，旧入口展开完整 `SkillLibraryScreen`，同时面对组合开关、安装、历史及单次设置。采用独立 `SkillQuickPicker` 放在输入旁，使用现有 `DraggableBottomSheet`；完整管理保留原路由，不新增导航目的地。

快速层只负责查找用途、编辑与确认下一条消息的选择；项目默认及全局启停在管理页中明确说明范围。全局停用复用现有撤销机制，并增加后果确认；项目取消选用保持只影响新运行的语义。

## 状态与来源

单次选择复用原存储、版本校验与消息受理事务，不新增第二份执行状态。唯一新增防护是确认时比较打开选择器时的会话范围与执行 epoch。管理往返保留未确认的短期编辑，返回后重读目录；输入组件始终挂载。已固定选择通过已有选择事件和运行事件刷新显示。

旧菜单技能管理入口、安装入口及深链接兼容；它们不被新快速层冒名替代。M2/M5 再迁移添加和历史任务，不一次重写领域服务。未采用“给管理页再加一组按钮”或“新建技能选用路由”，前者继续混合范围，后者增加短任务导航。

源码基线为 `db7aa4d6`；旧 beta.44/beta.47 截图保留原身份。验证任务、已测状态和未覆盖项见 [M1 合同与实现](../agent-m1-implementation.md)；更新指纹只表示已审查当前源码，不等于全部状态通过设备测试。

后续由 [D003](0003-skill-add-stages.md) 接入 M2 分步添加与 returnThreadId 来源身份；本决策保留 M1 当时合同与证据。
