# D004：以对象和差异组织修改建议

日期：2026-11-04。状态：M3a 已实施，限定设备验证；M3b/M3c 仍为提案。承接 D001 的助手建议流程及 F3，基于 M1/M2 提交 `e6fc2dff`；不替代授权、任务或候选领域规则。

## 问题与证据

同版本 Android 基线中，会话摘要将待审阅建议与成果混称；多张卡片同名“修改建议”，用户需逐个进入辨认。空草稿同时提供强生成入口；审阅页将未变字段也列入比较，处理后入口与终态缺乏连续性。见 [基线 01–03 与候选对照](../evidence/2026-11-04-m3-review/README.md)。

## 决策

保留现有组件、主题及路由，以项目/镜头身份、实际变更字段、领域状态组织卡片。待决策对象在前，具体动词作为下一步。新增目录子表面 `assistant-creative-cards` 登记原有弹层，不新增路由或独立执行状态。

审阅只突出修改字段；冲突采用原内容/当前内容/建议三方对照，阻止旧建议覆盖新版本。预读供理解，最终版本校验仍在原事务中。采用和拒绝后从数据库重读，保留终态、时间和原运行的固定对象入口；不靠乐观前端状态假报完成。

草稿先说明未提交、规格与待补内容。空描述只提供完善；已有描述继续使用原准备/确认能力，后续 M3b 再重组请求与许可。文字修改的采用不借此产生授权或生成任务。

## 取舍与验收

不将所有决策堆回消息底部：卡片负责发现对象，原项目活动负责完整差异。无需增加详情路由，代价是项目活动的普通日志仍在同一页面下部，完整诊断整理留 M5。终态建议继续可追溯，计划和候选的更完整生命周期留各自切片。
