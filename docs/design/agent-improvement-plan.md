# Agent UX/UI 改进实施计划

初版：2026-11-04；收尾：2026-11-05（Asia/Shanghai）。状态：M1–M5 的 Agent 50 项实现已完成并分部分提交，含最终补齐的第 43 项项目权限。当前结果以 [逐项收尾](agent-final-reconciliation.md) 和 [分阶段记录](agent-roadmap-completion.md) 为准；下文保留原排程与阶段门槛，不将历史“待办”段落视为当前状态。实施收尾时相关回归 70 套/600 项、类型与目录严格检查通过；后续 [改造后复核](agent-post-implementation-review.md) 扩大到 180 套/1063 项并修正计划状态及图片审阅。真实供应商与完整设备矩阵未验收。依据 [50 项初评](agent-action-review.md)、[流程合同](target-and-flows.md) 和 D001–D007。目标为 Android APK，使用现有主题、对象身份与执行能力。

## 目标与组织方式

让用户在当前项目中完成：描述目标 → 选择参考/技能 → 审阅建议 → 核对请求与许可 → 跟踪执行 → 审阅并采用候选。每个对象显示当前状态、阻塞原因及推荐下一步；管理能力进入明确的管理表面。

五层职责固定为：会话输入、提议审阅、计划处理、执行与成果、能力管理。层次不等于新增五个路由；短选择使用临时表面，长编辑使用完整编辑表面，对象详情复用现有页面。新增路由须先证明现有容器无法清晰承担任务。

本计划记录初始实施排程；用户认可后按切片完成全部实现，必要 M0 状态和离线证据随阶段补齐，覆盖边界单独记录。M1/M2 已提交为 `e6fc2dff`。进入每阶段设计时先补同版本现状截图，再做当前/建议状态对照；需要新视觉方向时遵循 Product Design 视觉选型流程，选定后才实现。既有 beta.44 截图只能用于旧版观察，不能代替当前候选采样。

## 分阶段执行

| 阶段 | 用户可感知的完成结果 | 对应评估项 | 前置条件 |
| --- | --- | --- | --- |
| M0 基线与状态合同 | 现状与目标任务可比较；状态与回流有明确规格 | 全部的验证前置 | 当前可运行测试包与隔离测试数据 |
| M1 会话与技能选用 | 保留输入，为下一条消息选技能并返回；范围不混淆 | 02、04、05、11–16 | M0 |
| M2 技能添加 | 选来源、编辑、检查、安装，完成回到原任务 | 18–21 | M1 的范围与来源合同 |
| M3 建议到候选的完整流程 | 建议、请求、许可、任务与候选可连续审阅和恢复 | 01、10、27–33、43–46、49 | M1；不依赖 M2 安装功能完成 |
| M4 计划与批次 | 单镜头先完成；批次准确说明提交集合、阻塞与暂停范围 | 34–42 | M3 的请求审阅、任务状态与返回合同 |
| M5 提炼、历史与诊断 | 长期复用与追溯清晰；输入工具与辅助表面一致 | 03、06–09、17、22–26、47–48、50 | 对应前序对象与状态合同稳定 |

推荐顺序 M0 → M1 → M2 → M3 → M4 → M5。若首轮以核心制作流程为目标，可在 M1 后先做 M3，再回 M2；M4 必须复用 M3，不另建第二套授权和任务展示。

### M0：补齐基线，先定义状态与返回

交付：

1. 记录当前提交、APK 版本/哈希、设备与测试数据来源，在独立测试环境补已配置会话、技能、待审阅建议、待授权计划、运行、失败、结果未知、候选等状态。离线样本与模拟状态逐项标注，不声称真实供应商端到端。
2. 每个对象写出“状态、主操作、次操作、禁用原因、作用范围、返回目的地”。复用既有领域状态；如 UI 需要派生状态，只做展示映射，不维护第二份执行状态。
3. 确定返回上下文：projectId/threadId、可选 shotId、draft/plan/run 标识、输入草稿及来源锚点。实现阶段再决定使用现有持久化或短期状态，不将敏感正文塞入路由。
4. 记录三条核心任务的找路次数、返回错误、完成情况与耗时：选技能并回输入、配置缺口恢复、建议到候选采用。先有基线再设改善目标。

验收：所有核心状态均有当前截图或具体阻塞；不会以旧截图填当前版本；已存在行为、缺证据和确定缺陷分开记录。此阶段仅需必要状态映射，不先建设全局 UI 框架。

### M1：会话输入与技能范围，作为第一实施切片

目标体验：项目在标题；镜头与下次技能在输入附近。点击“技能”只处理下一条消息，项目默认/全局管理有独立入口。

拆为两个可审查改动：

- **M1a 快速选用。** `PromptAssistantUi` 提供入口；从 `AgentScreen` 接入专用快速层。搜索、用途、选中项、作用范围、确认与取消即可；复用既有单次选择存储与有效性规则。完整 `SkillLibraryScreen` 不继续充当快速层。
- **M1b 范围与上下文。** 项目默认组合与全局启停明确分组；内置保持可发现、只读。调整 `AgentCreativePanel`/`AssistantActions` 与镜头范围展示。全局停用解释关联运行影响，项目取消选用只说明后续运行影响。

首批状态稿至少包含：项目继承、编辑未确认、空选仅内置、已固定单次、版本失效、管理返回、运行锁定。不要仅做一个“选中状态”画面。

验收任务：输入文字并加附件 → 开快速层 → 选择 → 确认 → 回输入 → 发送一次。确认前关闭不写选择；空选含义明确；单次选择只按既有规则消费；全局/项目组合不被误改；进管理再返回仍保留输入和未确认选择。覆盖系统返回、键盘和切后台重开。

### M2：添加技能按阶段呈现

目标体验：目录“添加”→ 导入/手写/提炼入口 → 对应编辑 → 校验预览 → 安装 → 新版本详情。原目录不在编辑表单下方继续延伸。

主要修改 `SkillLibraryScreen` 的表面组织，复用安装校验、不可变版本与草稿保护；提炼入口先连接既有能力，完整提炼重组留到 M5。不要为视觉拆分而复制安装服务。

验收：导入取消、格式错误、已有正文填示例、安装失败、编辑退出、新版本定位均可恢复。安装成功不自动启用；来自会话时可明确选“用于下次消息”，也能只安装后返回。手写的本地模板按钮用“创建草稿”，与调用模型区分。

M2 已实施，见 [实现与验证](agent-m2-implementation.md) 与 [D003](decisions/0003-skill-add-stages.md)。141 项相关测试通过；设备完成导入取消、格式错误、覆盖确认、键盘检查、安装定位及明确选用于原会话。安装失败、范围漂移由集成测试覆盖，未声称设备故障注入完成。

### M3：连接建议、请求、许可与成果

目标体验：会话内先看到对象和状态；需要用户决策时出现具体动作。提议、草稿、任务、候选各有清晰称谓与稳定身份。

拆为三个改动，逐条完成任务：

1. **M3a 提议与草稿卡。** `AgentCreativeCards`、`ProjectActivityPanel` 呈现对象、差异、影响与状态动作。采用修改/拒绝只影响提议，不改变生成许可；泛化“查看并处理”改成实际下一步。
2. **M3b 请求审阅与配置恢复。** 将单次/计划授权所需信息整理为可滚动审阅表面，复用现有 prepare/confirm 与修订校验。明确服务、当前账号、输入版本、规格、次数、有效期、费用；外发许可与消费许可分别表达、分别记录。缺配置直达所需用途并返回原请求；配置保存不提交。项目全部授权撤销归权限管理。
3. **M3c 执行到候选。** 区分助手运行、生成任务、本地归档、候选与采用；运行给阶段和适用的停止操作，未知结果给查询原任务，确定失败才准备新尝试。候选进入原有审阅并明确采用，保存手机单独处理。

验收：完整成功链、拒绝/取消链、版本冲突、缺连接往返、结果未知查询、离开后恢复各完成一次。退出审阅不提交；重复确认不新增意外请求；采用固定候选版本；停止助手不假报服务端任务已取消；历史记录不随当前连接或技能改变解释。

M3a 已实施，见 [实现与验证](agent-m3a-implementation.md) 与 [D004](decisions/0004-agent-proposal-review.md)。9 套、58 项相关测试及类型检查通过；隔离 Android 样本完成项目/镜头采用、拒绝、三方冲突、终态回访和空草稿编辑。此为 M3a 当时的验证范围；请求/候选后由 M3b/M3c 接续完成，不能把该阶段证据扩大为完整 M3 设备验收。

2026-11-05 续：M3b1 会话单次草稿改为可滚动请求审阅、外发/消费分别勾选及原位账号恢复，见 [实现记录](agent-m3b1-implementation.md)。31 项相关测试与类型检查通过；设备使用离线 prepare 替代，仅验证界面与取消回流。这是 M3b1 的历史范围；计划/批次、视频工作流快照及配置恢复后由 M3b2 接续完成，图片参数补齐见复核报告。

### M4：计划列表与详情分工

目标体验：计划列表显示镜头/批次、进度、阻塞与推荐动作；进入具体计划后再处理输入、依赖和执行控制。

拆为两个改动：

- **M4a 单镜头。** 从 `ProjectPlans` 提取列表行与详情表面，按准备参考→核对输入→检查/依赖→授权→执行→审阅组织。进入选图自动读取候选；依赖编辑使用可搜索对象列表。当前镜头变化与失败重做各有明确状态动作。
- **M4b 多镜头。** 复用单镜头准备和 M3 请求审阅；批次显示总范围、实际提交集合、暂停/缺图/未就绪项。尤其验证跨分页：授权文案必须与实际请求集合一致，不能将当前页称作全部批次。

验收：先单镜头，再批次；覆盖无参考、依赖未就绪、依赖循环拒绝、输入过期、部分失败、暂停/恢复、取消、分页与旧链接定位。暂停只阻止后续提交；已发任务继续有状态入口。列表/详情使用同一计划事实来源，不各自计进度。

### M5：辅助能力收口

拆成三组，避免一个大改动同时触及所有会话表面：

- **M5a 提炼。** `SkillExtractionScreen` 分选证据、核对外发、审阅、发布阶段；保存草稿列表独立。发布后进入 M2 的固定版本详情，选用继续使用 M1。
- **M5b 历史与诊断。** 技能运行记录归会话运行历史；`SkillRunScreen` 先结果摘要，再阶段，最后原文。保留 `ActivityGroup` 已有折叠；项目活动说明已发生事实与待处理建议。
- **M5c 输入与版本。** 会话管理、图片引用、简报、全屏编辑、Prompt 版本统一入口、退出与焦点规则。复制/带入只预填，不借此直接生成。

验收：提炼取消和重开不丢已存草稿；检查/发布/安装/选用语义分别成立；历史保留筛选、分页与消息锚点；运行终态变化在已打开详情中可见；版本与实际读取来自当次记录；长输入与附件引用不被导航破坏。

## 每个切片的工作顺序与完成门槛

1. **规格。** 核对对应评估项、当前源码、同版本截图、状态/范围/返回合同，明确本次不涉及的相邻任务。
2. **设计。** 给出同任务的当前/建议状态对照；必要时完成视觉选型；做最小可点原型，只验证该任务与关键异常。设计验证不等于产品验收。
3. **实现。** 一次合入一条可独立审查的任务链；复用对象、授权与持久化。保留旧链接，迁移入口指向精确对象，不只返回首页。
4. **验证。** 对实际变化的领域/交互契约补必要回归，运行类型与相关测试；设备完成成功、取消、阻塞、冲突及重开等适用路径。低影响文案/布局不添加只复刻实现的测试。
5. **谱系。** 更新相关目录条目、点击边与 F3/F4/F5 等合同；发生实质结构决策时新增 D002…，说明承接/替代 D001 哪一部分。源文件审查后才能更新指纹；生成逐页报告后检查一致性。
6. **交付。** 记录提交、候选 APK 身份、设备、截图、实际任务结果和未覆盖项；只对已达标表面标记 implemented/device-verified。保留上阶段可回退代码与数据兼容性。

文档检查使用 `node scripts/design/check-page-catalog.mjs`；修改目录后使用 `--write` 再检查，源码审查后使用 `--check-sources`。设备建议 360–400dp，字体 1.0/1.3/2.0；覆盖键盘、系统返回、长标题、安全区与 48dp 触控布局目标。TalkBack 验证焦点进入/返回、范围、选中、禁用原因与运行状态播报；截图不证明这些交互通过。

## 初始排程判断（历史）

初始排程以 M0 + M1 为首轮，继而逐步完成 M2、M3a、M3b1。2026-11-05 已继续完成 M3b2、M3c、M4、M5 及第 43 项补齐；实现顺序和每次验证见逐项收尾，不以离线样本代替全量设备/线上验收。

M1 结束后，用实际设计、实现、设备验证耗时估计后续工作。每次排程同时计入状态设计、实现、失败/返回验证与谱系更新，不能只按界面编码时间估算。角色分为设计/交互、实现、审查，可由同一人承担，但完成记录仍分开。

若按完整 Agent 工作台对外介绍，M3/M4 的请求集合、许可、未知结果、暂停语义与候选采用必须验证；较低频的 M5 视觉整理可以后续推进，相关既有正确性回归仍要保留。正式发布另遵循仓库的升级与候选验收门槛；此 UX 计划不是发布许可。

## 完成判据

用户能说清“当前作用哪个项目/镜头、下一步做什么、会不会提交/消费、完成后到哪里”；核心任务可从入口完成并可靠返回；输入、版本、许可与历史不因界面重组而变化。以任务完成与误操作改善衡量，按钮总数只作为辅助观察。

2026-11-05 续：M3b2 计划/批次已接入同一请求审阅及配置恢复，50 项相关测试通过，离线设备核对请求范围与取消。见 [续作记录](agent-roadmap-completion.md)。

当前实施闭环：参见 [01–50 最终结果与提交链](agent-final-reconciliation.md)。保留原阶段规格供后续维护，不能以历史切片的未完成描述覆盖最终状态。
