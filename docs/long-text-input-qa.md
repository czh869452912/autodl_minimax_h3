# 2026-10-26 长文本输入与编辑界面修正

## 问题与处理

- 共用 `KeyboardAwareScrollView` 原先将超高输入框的顶部拉回视口，不能代表用户点击的实际编辑位置。Android 新增原生 selectionEnd 行测量（考虑文本内滚动、padding 与屏幕密度），通过 React tag 定位输入框，兼容独立 Modal；只滚动需要避让的光标行。原生测量不可用时保留长输入框当前可见部分，不再强行回到顶部。
- 共用滚动组件及视频、创作表单、参数弹窗、助手表单取消 on-drag 收起键盘，允许滚动时继续编辑。
- 提示词主标签固定为“正向 / UC · 负面”，不因角色数量变化切换 Base Prompt。单行分段控件明确单行排版与有限字体缩放，避免文字被切掉。
- 图片导入集中在“参考图”页，删除标题栏导入和图生图区域重复上传入口；“从素材选择底图”保留，因为来源不同。蒙版导入保留独立语义。
- 用户截图的 NativeDatabase.prepareAsync 失败发生于语句准备阶段。只对此阶段 shared object already released 错误重试一次；执行/最终释放阶段不重试，避免已写入操作重复。锁冲突仍使用原来的有界重试策略。创作页和同步轮询使用统一友好提示，不将原生堆栈铺满页面。
