# 视频生成交互、结果管理与提示词协作评估

## 当前问题（基于代码）

- `VideoDraftScreen` 已用 `videoSessionDrafts` 收集同一创作会话的素材 ID，再交给 `CreativeResults` 查询版本。旧结果并非必然被覆盖。
- `CreativeResults` 的 canvas 分支只有图片会显示常驻缩略图、上一张/下一张控件；视频需要进入“更多成果操作 → 版本历史”，所以用户容易认为只能看最后一次。
- 选择依据主要是最新 `resultDraft.job_id`，且 job_id 变化时重置 selected；继续提交可能打断正在看的旧结果。
- 当前任务状态来自最新 draft，预览则可能是历史版本；“本次生成参数”、复制草稿、状态与素材操作的归属容易混淆。
- 素材的 versionNo 是每个 asset 内的编号。跨工作流可能有多个“v1”，不能充当创作会话中的轮次。
- 仅查版本无法展示还未产出文件的排队、失败或取消轮次。

## 推荐布局

保留“创作 / 生成记录”两处内容区，把“本次进度”改为稳定的“生成记录”。结果区只放一个主播放器，下方固定一条可横向滚动的轮次栏，不需要先打开抽屉。窄屏每屏约3项，宽屏可变成右侧记录列；列表使用虚拟化。

每个轮次包含封面、轮次号、状态、排队与运行时间。完成结果使用视频封面；未完成轮次用状态占位，不实例化视频播放器。文件准备/下载失败区别于生成失败，可单独重试下载。主播放器旁边显示该轮的模型/工作流、时长、分辨率及创建时间。

点击旧轮次直接切换播放器及该轮信息，保持创作输入不变。再次生成后，在列表中插入新轮次；用户已经手动选中过去的结果时保留其选择，用“有新结果”提示。只在未手动选过结果时自动跟随最新完成项。失败的新任务不隐藏之前可播放的结果。

## 数据与操作归属

- 会话：优先使用持久化 sessionId，限制项目、镜头和供应商范围；旧草稿按已有 target_asset_id 回退分组。不把所有视频任务混进一个列表。
- 轮次：以不可变 jobId 为主键，提交时间及稳定次序编号，与 asset/versionNo 分开。每轮可以有多个输出 versionId，界面可在该轮下切换。
- 查询提交草稿、任务、输出版本的关联视图：包含未完成轮次；复用已有 startedAt/executionDuration 和时间展示逻辑。未记录的时长显示“未记录”，不伪造为0。
- 预览、参数、保存、查看任务、复用输入全部指向选中轮次。复用需要明确点击“复用本轮”，不会因浏览历史覆盖正在编辑的内容。
- 仅当前选中结果挂载 VideoPlayer，切换时停止旧播放器；封面复用现有 MediaPreview 缓存。
- 浏览选择用 selectedJobId/selectedVersionId 单独保存，不与最新任务指针混用。新增任务、乱序完成、返回页面、应用重启均保持稳定选择。
- 删除记录与删除本地文件分别处理；项目已采用或作为参考输入的文件不能在普通清理中直接删除。

## 提示词助手挤压生成栏：确认原因与布局方案

`VideoDraftScreen.tsx` 先渲染 `v.footer`，随后在同一纵向布局内插入高度320、最大55%的助手 View。助手不是覆盖层，所以打开后占用高度，把“生成 X 秒视频”整行顶到中间；键盘出现又进一步压缩编辑区域。这不是调整几处 margin 能解决的问题。

推荐把主内容、助手覆盖层和底部操作区分开管理：

- 窄屏助手使用覆盖式可拖动面板，默认停靠中上位置，覆盖表单或预览，不参与背景内容的高度分配。复用图片编辑抽屉的交互原则，不再在 footer 后插入普通块。
- 键盘关闭时，生成栏仍固定在底部安全区；助手面板下缘停在生成栏上方。助手的发送栏在面板内部，明确区分“发送给助手”和“生成视频”。面板与背景控件不重叠响应点击。
- 键盘打开时，以助手输入框为主：其发送栏贴合键盘上缘，暂时隐藏背景生成栏，避免两排操作挤在键盘上方。隐藏不卸载草稿，不改变生成参数；关闭键盘后恢复底部生成栏。
- 关闭助手时先解除输入焦点与键盘避让，再收起覆盖层；恢复原表单滚动位置，不重新对齐到长文本开头。系统返回先收键盘，再关闭助手，再离开页面。
- 宽屏在内容区域覆盖右侧面板，底部生成操作保持稳定；小屏、横屏和大字体时允许助手展开到顶部安全区，消息区独立滚动。
- 图片与视频使用同一助手容器规范，保留各自的编辑器内容。禁止同时叠加助手、设置、素材选择等多个面板；打开新面板时保存当前状态再切换。

不建议仅将助手移到 footer 前面：虽然按钮能回到底部，背景区域仍会被压缩，键盘展开后的高度竞争仍然存在。

## 图片/视频 AI 辅助：独立讨论与上下文隔离

### 当前实现与风险

两个入口均使用共享的 `PromptAssistSheet`。页面传入 `image:${initialId}` / `video:${initialId}`，`promptAssistantSession.ts` 将该 ID 对应的消息保存为一个文件；组件没有讨论列表、新建讨论或重置入口。每次发送都沿用当前消息，最近24条的截断只限制数量，并不隔离创意。已有上下文指纹用于阻止过期建议直接应用，不会阻止旧讨论影响新的回答。

固定路由 initialId 也不适合充当长期讨论身份：编辑副本、重新进入和切换工作流可能改变路由或上下文，却没有清晰的讨论归属规则。需要区分“同一创作的多轮生成”和“同一创作的多次AI讨论”，不能简单把两者都叫 session。

### 推荐入口与行为

助手标题栏显示“当前讨论标题 ▾”，旁边保留“新建讨论”和关闭按钮。点击标题在面板内部切换到紧凑的讨论列表，不再额外叠加抽屉；助手模型设置进入更多菜单，避免在窄屏标题栏堆按钮。

- **新建讨论**：保留旧讨论，创建独立 conversationId、空消息和空待发送文本，清除未采用建议、错误状态及该讨论的撤销状态。保留画布/表单中的当前提示词与参数，新讨论默认可读取它们；不携带旧消息、摘要或工具结果。显示“使用当前草稿 · 不包含其他讨论”，避免用户误以为新建会清空作品。
- **切换讨论**：恢复该讨论的消息、未发送文本和滚动位置，不自动修改草稿。标题取首条要求，支持重命名；按最近使用排序，并标记图片/视频及对应工作流。
- **重新开始**：以“新建讨论”作为默认入口，不把“清空记录”作为唯一重置办法。删除讨论放在更多菜单，确认后删除；删除讨论不删除生成结果或草稿。
- **上下文变化**：同模型下微调提示词仍可继续当前讨论；跨图片/视频必须隔离，跨工作流或明显切换创作目标时提示新开讨论并默认新建。若选择继续，明确显示上下文已变，不悄悄合并。
- **历史建议**：应用前验证当前草稿指纹及版本；不匹配时提示“草稿已变化，请基于当前草稿重新调整”，不能用旧回复直接覆盖新内容。新讨论不能撤销另一个讨论的修改。

“不污染上下文”指旧讨论消息不进入新请求。当前草稿若已经采用了旧建议，其内容仍是当前作品的一部分，默认保留；想从完全空白开始应使用“新建创作”，不能偷偷清空用户输入。

### 存储与异步边界

- `workspaceId` 绑定稳定的创作会话（图片素材探索、视频 sessionId，包含类型与项目/镜头范围）；`conversationId` 为独立 UUID。讨论索引保存标题、创建/更新时间、kind、workflow、归属和 activeConversationId，消息按 conversationId 独立存储。
- 请求只读取选中讨论的历史与发送瞬间的当前草稿快照。预算截断/摘要仅作用于该讨论，不跨讨论检索或拼接。
- 新建/切换时停止旧请求，并使用 conversationId + requestId/epoch 双重校验流式回调。只检查 mounted 不够：组件仍挂载时，旧请求的 finally、错误或延迟消息也不能覆盖新讨论。
- 未完成回复最多作为“已停止”的消息写回原讨论；消息写入队列按 discussion ID 隔离，旧请求不得写入新讨论文件。
- 采用建议与撤销记录绑定讨论、目标草稿和基线指纹，切换创作后不能误应用。
- 旧单文件记录迁移为一条“已有讨论”，采用可重入迁移标记；迁移失败保留原文件并允许重试，不能静默清空。归属不能可靠推断的旧记录保留在原草稿下，不任意并入另一创作。
- 首轮实现本地讨论管理即可，无需将手工模式的轻量提示词协作改造成完整 Agent 工作台；两个图片/视频入口共用会话管理能力。

## 视频创作区的整体交互优化

1. **明确当前编辑对象**：生成提交后输入用于下一轮，已提交快照不可变。使用稳定的“创作 / 生成记录”标签，不在“本次进度/结果”等名字间跳变；用小计数或状态标记表达后台进度。
2. **参考素材集中管理**：图片和音频各自一个添加入口，直接打开对应的多选选择器；已有素材库作为该入口的来源选项，避免页面同时平铺“添加/从素材选择/加号”多个同义控件。必要的来源选择不再要求重复选择媒体类型。缩略图就地移除、排序、预览，保留最大数量及必填约束。
3. **减少参数抽屉**：时长、画面方向、清晰度采用同一紧凑参数区。两三个固定选项用就地切换，复杂数值才展开；低频参数放“更多设置”。按工作流实际 schema 显示，避免强行套用固定 H3 参数。
4. **助手就地应用**：“帮我写”靠近镜头提示词，只设置一个入口。建议采用后保留面板供继续讨论，用轻量提示反馈；用户关闭才回表单。采用不是生成，不增加第二个“生成”按钮。
5. **底部状态收敛**：固定生成按钮，状态文字只显示需关注的保存/校验/账户问题。避免重复显示“正在生成”长说明；并行任务交给任务入口和轮次栏表达，不把旧任务运行状态当成下一轮提交限制。
6. **滚动与键盘统一**：长提示词保持光标可见、滚动不强制收键盘；助手和表单各自保存滚动位置。开关面板不改变后台播放器尺寸、不触发自动播放或重新读取整个工作区。
7. **错误按位置呈现**：参数校验贴近字段，素材失败贴近缩略图，某轮失败显示在该轮。数据库或网络内部错误不能占满表单顶端；读取失败保留已读内容并提供简短重试入口。

## 建议实施顺序与验收

1. 优先修复助手挤压生成栏，并增加图片/视频共用的独立讨论管理与异步隔离；这些属于直接影响输入和上下文可靠性的问题。
2. 补齐会话轮次查询、直接可见的记录栏与选中归属，覆盖已完成、运行中和失败轮次。
3. 增加选择持久化、新结果提醒与复用入口；沿用系统相册导出能力；统一素材入口和参数区。
4. 数据量上来后再补筛选和批量清理，避免先堆积按钮。

验收：连续提交3轮、乱序完成；播放第1轮时第3轮完成不能抢占；第2轮失败仍可看第1轮；跨工作流两个v1能够辨认；返回或重启后可选回旧结果；只有一个播放器运行；参数/时长/导出/复用均对应选中轮次。

助手布局验收：打开/关闭、拖动、键盘展开/收起、横竖屏和大字体时，生成栏不被顶到中间；键盘打开仅助手输入栏贴键盘，关闭后生成栏回到底部；长文本光标与滚动位置保持；背景不因面板展开而缩放。

讨论隔离验收：A讨论要求红发，B新讨论在相同草稿下不收到A消息；返回A仍可看到历史；A流式输出中切换B，延迟回复及finally不能改变B；旧建议不能覆盖变更后的草稿；新建不丢旧记录，重启可恢复索引与草稿；旧文件迁移重试不重复创建；图片和视频永不混用历史。应检查实际发送的消息列表，不能仅用界面“看起来清空”作为通过依据。
