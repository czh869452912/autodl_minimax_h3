# UX 改版后的端到端配合复核

## 本轮发现与修复

1. 视频编辑器能够显示兼容工作流的额外参数，但 AutoDL 请求映射仍只保留 H3 的固定字段。现在发送编译后的全部服务端绑定，保留 `0`、`false` 等值；图片和音频继续映射到对应参考槽，不发送素材的本地描述对象。
2. 图片生成、Enhance 和独立超分此前只检查账号记录是否存在，缺少安全存储秘密或原生能力时可能先生成任务。现在准备与确认两处解析具体凭据代次、检查原生端点；后台的本地参数检查也在消费发送边界前执行。
3. 兼容旧创建页的新任务仍依赖执行时的默认 AutoDL 账号。现在提交操作只保存账号 ID、凭据代次、服务商；后台提交、状态同步和下载地址刷新解析同一代次。明确重建的新尝试经过预检后绑定当前账号。历史无绑定记录仍走兼容路径，不猜测其原账号。
4. NativeModule 明确返回 NovelAI 参数、鉴权、额度或限流拒绝码时，此前被通用异常转成 UNKNOWN。现将明确拒绝转为 FAILED，并展示对应处理建议；超时、连接中断及上游失败仍保留 UNKNOWN，不自动重复消费。
5. 切换视频工作流后的结果历史以各素材自身的版本号混排。现在读取版本创建时间并按时间排序，避免旧素材 v9 排在新工作流 v1 前面。
6. 窄屏实机停留时复现 `NativeStatement.runAsync` / `Cannot use shared object that was already released`。本机安装的 expo-modules-core 为 57.0.16，与官方已确认的 Android 异步 SharedObject 生命周期问题吻合。锁定到包含修复的 57.0.22，配套 expo-modules-jsi 由锁文件固定；不通过盲目重试数据库写入掩盖问题。参考 [官方修复 PR #50513](https://github.com/expo/expo/pull/50513) 与 [SDK 57 更新记录](https://github.com/expo/expo/blob/sdk-57/packages/expo-modules-core/CHANGELOG.md)。

## 复核范围与证据

| 链路 | 核验结果与方法 |
| --- | --- |
| 手工图像编辑 → 请求 | 组件测试覆盖最新编辑先保存、直接提交、重复点击只提交一次、批量数量、Medium、运行中编辑派生副本；协议测试覆盖 V5 Full、角色、参考图、蒙版及采样配置。 |
| Enhance / 超分 | Enhance 发送原图像素与独立输出尺寸；独立超分使用自己的端点与原生收据；缺秘密、准备后断开账号、缺原生端点均在任务与授权创建前停止。 |
| 视频工作流 → HTTP | 新增真实 SQLite 集成测试，从动态表单值与图片/音频引用进入 prepare/confirm、持久化队列、绑定执行器、HTTP 序列化、轮询与归档。HTTP 使用测试传输，断言 URL、完整请求体与单次 POST。 |
| 草稿和运行任务隔离 | 图像/视频组件测试确认自动保存下一次输入不修改运行中快照；切换工作流恢复各自输入，版本变化拒绝直接提交。 |
| 新旧入口账号一致 | 生产 application executor 回归确认旧入口任务使用固定凭据，切换默认账号不改变提交或查询；凭据撤销时未发送任务 FAILED，零 HTTP。查询与下载刷新共享绑定解析。 |
| 任务状态与恢复 | 明确拒绝 → FAILED；无法确认受理 → UNKNOWN；有句柄查询不重新生成；无句柄显示核查；未跨发送边界的本地失败释放 RESERVED。既有恢复测试及 5 类独立进程恢复验证。 |
| 成果 → 素材管理 | 完成结果按任务、输出 ID 幂等归档；随机种子、生成参数、原始元数据与输出尺寸分别保存；跨工作流历史按时间排列。已有真实服务响应仅离线回放，不新增付费请求。 |
| 保存到相册 | 原生发布收据与哈希检查、重复保存幂等；任务 UI 与归档完成分离。SQLite / 原生单元测试覆盖，图片预处理与发布另由 Android 仪器测试核验。 |
| Agent 工作台 | 保留项目 → 对话入口；进入已有项目不创建生成草稿。现有计划测试覆盖用户决策冻结、授权、并发只提交一次、账号切换/恢复/取消不自动消费。此轮未扩展 Agent 的生成能力。 |
| 设置与导航 | 窄屏检查统一账号入口、设置主页和工作流管理；事故前检查了原 UNKNOWN 返回工作台及下一次输入，没有手动修改其核查状态。该记录后来因测试卸载丢失，见恢复说明。恢复后复查双工作台、视频高级参数与冷启动。 |

## 验证事故与部分恢复

本次调用 `connectedDebugAndroidTest` 时，AGP UTP 默认生成了 `uninstall_after_test: true`，测试结束卸载了目标应用并删除模拟器中的应用私有数据。执行前没有制作完整快照，这是本轮验证方式的错误；应用业务代码并非删除原因。

已重新安装最终包，并从本机 2026-10-24 17:32 的 `.local-tools/enhance-device-debug.db` 恢复数据库。该备份包含 1 个项目、2 个素材、3 个素材版本、12 个草稿与 1 个已完成任务。备份中全部 3 个原件均从本地已有文件/响应中找回，SHA-256 与数据库记录完全一致；完整性检查为 ok，外键错误为 0。

恢复使用产品已有的 `quarantineRestoredExecution`：更新执行 epoch、隔离历史任务和操作、撤销旧授权并清除默认账号；不自动重放生成或相册发布。原备份保持不变，恢复副本与检查报告保存在被 Git 忽略的 `.local-tools/ux-audit-recovery/`。

这只是部分恢复：备份之后产生的任务、草稿改动与设备安全存储设置无法由该备份完整还原，包括本轮先前仍存在的无句柄 UNKNOWN 视频任务。其描述、时间与页面状态有本次截图记录，但没有伪造数据库记录或把它标记为已核查。卸载删除的安全存储凭据也不能通过数据库复制恢复。

已使用用户此前授权的本地 `.env` 重新连接 NovelAI 与 AutoDL，账号页面分别显示“已连接”和“已绑定”。NovelAI 只执行只读账号验证，AutoDL 按现有产品逻辑绑定后等待首次服务请求验证；没有触发付费生成。重新连接产生新的凭据记录，不等于恢复旧安全存储代次。已在停止应用写入后保存恢复环境的私有文件备份：`.local-tools/ux-audit-recovery/recovered-app-private-2026-10-25.tar`，未提交到 Git。

已在 `android/gradle.properties` 设置 `android.injected.androidTest.leaveApksInstalledAfterRun=true`，防止后续 UTP 自动卸载；依据 [AndroidX 官方保留 APK 配置](https://android.googlesource.com/platform/frameworks/support/+/eb74b1a4b3527414639994574a201f125aff90f5)。没有为了验证此配置再次在恢复后的用户环境运行同类仪器测试。

## 验证边界

此轮不新增付费图像或视频生成，不把模拟传输与既有真实响应回放描述为所有远端 API 的在线验收。原无句柄 UNKNOWN 任务是否已被服务端受理仍需用户在服务端核查，不能从本地记录推断。新增任意第三方工作流还需其自身服务端协议验收；本轮证明兼容字段能够完整到达 HTTP，不宣称其服务端都支持这些字段。
