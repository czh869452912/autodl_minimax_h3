# 生成工作台第二轮交联复核

本轮继续检查工作台返回、工作流目录变化、发送前异常、后台阻塞恢复与结果观察。沿用统一任务执行器和账号绑定，修复的是页面与持久任务事实之间的断点，没有新增提交后端。

## 发现与处理

| 问题 | 修复及回归证据 |
| --- | --- |
| 发送前凭据失败没有进入通知队列 | 执行器写入的 `SUBMISSION_FAILED` 与 SQLite 通知触发器及读取器要求的 `SUBMIT_FAILED` 不一致。统一事件名称；真实 SQLite 回归验证任务 FAILED、预算 RELEASED、通知可读且没有 HTTP 请求。通知文案改为“生成任务”，兼容图片与视频 |
| 凭据读取中的短暂数据库锁被当成永久凭据失效 | 已解析绑定后，`SQLITE_BUSY` 也会进入凭据失败分支。现在交给 runner 重试；真实 SQLite 回归验证首次保留 READY_TO_SUBMIT 和 RESERVED，重试只发送一次，且不发失败通知 |
| 未发送但已 BLOCKED 的请求持续占用工作台 | 恢复曾仅识别一个特定错误代码。现在依据当前执行 epoch、RESERVED、无远端句柄及阻塞操作识别未发送请求，结束本地任务并释放预留。已发送或结果不确定的预算不会按此规则释放 |
| 恢复扫描与发送之间存在竞争窗口 | 在恢复候选扫描后重读任务状态、阻塞操作，并以任务 revision 转换作隔离。回归模拟扫描后进入 SUBMITTING / DISPATCHED，确认恢复不再修改它。若进程在任务转换后中断，下次恢复仍可完成操作收尾和预算释放，重复执行不发请求 |
| 视频工作流缺失影响已有任务观察 | 原逻辑先解析工作流和验证参考素材，失败时尚未恢复结果草稿。现在先恢复已有提交及成果观察，再加载编辑依赖；组件回归验证缺少工作流时已有任务仍显示在结果画布 |
| 返回工作流设置后目录不更新 | 草稿版本未变时，原草稿同步不会重载目录。现在页面获得焦点时单独刷新工作流及版本状态，保留未保存输入；重新安装缺失工作流后可恢复编辑器，不自动提交。目录错误独立管理，恢复后清理，手动重读也复用草稿同步的 reload 操作 |
| 结果刷新重叠及过期错误提示 | 慢查询允许下一轮刷新并发进入，可能由迟到结果覆盖新状态。现在同一观察周期串行刷新，失焦后的结果不应用；读取错误与操作错误分开，自动重试成功只清理读取错误。假时钟回归覆盖慢查询和短暂读取失败 |

## 旧结构复查

未发现重新引入第二套生成账号入口或执行器。`autodl.token` 的生产引用仍限于账号模块的历史迁移与清除；设置和兼容表单不再传递 Token。生成调用继续通过 `providerExecution` 和应用 provider registry，只有确实无绑定的历史任务保留默认账号兼容。

旧 handoff 编辑器、任务读取投影、旧媒体到 CAS 的桥接仍有生产消费者，暂不删除。其迁移条件和职责见[上轮复核](2026-10-25-frontend-backend-recheck.md)。本轮删除的是对旧错误代码的单点恢复依赖，以及视频通知专属文案，没有新增通用抽象层。
