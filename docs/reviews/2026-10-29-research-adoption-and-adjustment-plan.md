## 1. 决策

采纳总体方向，但调整实施顺序：**现有对象与结果正确性 → 创作入口与返回闭环 → 辅助交互 → 最小运行边界 → 本地技能闭环 / 静态 3D 验证 → 持久流程扩展。**

导航报告中的可达缺陷应落地；架构研究中的能力缺口不等于当前故障。先修会误看、误操作版本或丢失来源的问题，再扩展能力。继续保留共享命令、任务持久化、版本资产、预算授权与 Provider 适配，不更换整个技术栈。

沿用报告记录的全本地约束：远端仅处理模型及必要输入上传、任务查询和结果下载；不引入业务服务器、远端 Agent、运行时 CDN。独立快速生成不强制创建项目。

对原报告路线作以下调整：

1. N05 从 P2 提升到首批：旧任务显示其他轮次结果，会使画面与任务状态、费用归属不一致，优先级应与 N02/N06 相同。
2. N08 按“显式打开意图”修复，不在每次 focus 时强行恢复最近草稿。返回原画布与继续最近工作是两个合法动作。
3. R01–R04 提前进入相关批次的验收，不等最后再发现隐藏 Tab、Stack 与硬件返回不一致；未经设备复现仍标为风险。
4. 不把完整 RuntimeAdapter/服务分层重构放在导航修复之前。只抽取当前批次实际需要的契约；禁止为未来平台一次拆完全部 service。
5. DeepAgents 升级成为独立技术验证，不是导航、技能存储或 3D 的前置条件。沿用报告的固定候选 1.16.0 作实验，不将其称为本次核实的最新版本。
6. 技能首个可用交付必须包含“导入 → 固定版本 → 在新运行中使用”；仅有安装器和列表不算闭环。提炼、通用角色编辑、多 Agent 后置。
7. 3D 先做离线静态取景验证。正式 PNG 接入只要求最小场景版本与资产来源契约，不等待通用流程、无限画布和时间线全部完成。
8. 项目包/备份契约前移到新增持久实体之前，完整备份 UI 可以后置；避免技能、场景引用无法随项目恢复。

## 4. 近期实施批次

### P1：结果身份正确性

交付顺序：P1a 任务范围与失效版本（N05/N06）→ P1b 精确候选打开（N02）。每项可独立提交，不等待入口统一。

落点：`AgentCreativeCards`、视频草稿 route/`VideoDraftScreen`/`VideoGenerationHistory`、任务 route、`CreativeResults`、`CreativeWorkspace`，以及对应测试。

- 建立最小 OutputTarget：assetId、versionId、关联 jobId、可选 projectId/shotId；读取时核对相互归属，不信任路由参数组合。
- 明确传入版本优先于本地历史选择；同 job 切换候选也更新。指定结果不在已加载分页中时按 ID 查询，不能把“没加载到”误判为删除。
- 区分记录缺失、文件缺失/待恢复、无权使用或对象不匹配；阻止对其他版本误导出、误采用、误处理。
- 任务历史以 jobId 限定；多产物/部分成功正常展示，完整历史入口明确离开任务范围。

验收：同素材两个任务、每任务两个候选，连续 A/B/A 均显示精确版本；旧任务不出现新任务产物；版本缺失不回退；文件待恢复不显示成记录删除。组件测试外，真实导航至少覆盖同路由参数更新。

### P2：统一创作入口与输入保护

落点：create route、`CreativeHome`、`AgentScreen`、旧 draft/handoff 读取、视频工作台创建入口、gallery route。先落转换服务，再替换入口。

- 增加一次性 OpenCreativeRequest，区分恢复草稿、恢复某媒体最近工作、新建、导入 handoff；携带 requestId，完成后消费，重复投递不重复建草稿。
- 旧 draftId 与正式创作 draftId 使用明确类型/转换映射，不能当作同一个 ID；来源记录保留。附件、工作流及其参数逐项映射，无法兼容时展示预览与原因。
- 项目/镜头绑定来自明确选择或可靠来源，校验其存在及归属；不从当前 Tab 猜测，不修改原 Agent 会话范围。
- 请求执行前等待当前编辑保存；失败时保持原输入和请求待处理，不清除来源草稿。Prompt/媒体正文不放入新路由参数。
- 普通返回保留 active；“打开 B”明确切到 B。覆盖图片模式下进入“去生成视频”。

验收：旧 Prompt/附件草稿可恢复；重复导航/重挂载只生成一份目标草稿；输入后立即导入另一草稿不会丢失；保存失败不会继续切换；整个流程不自动提交生成。

### P3：镜头—结果—续作—返回闭环

落点：`WorkbenchScope`、`CreativeResults`、`ProjectShots`、任务/草稿 routes、`VideoDraftScreen`；在 `src/navigation/` 增量集中打开与返回规则。

- 复用 P1/P2 契约，补 openProjectObject、returnToOrigin；来源含稳定对象 ID、进入意图及轻量视图锚点。返回锚点不是授权。
- 有可验证来源实例时回到该实例并恢复镜头/选中项；孤立深链、重启、来源已移除时按“对象→所属项目→列表/工作台”有效性选择兜底，并说明失效。
- 具体 Expo Router 导航原语由当前安装版本与真实 Stack/Tab 探针决定；先验证再实现，不预先承诺一个 replace/dismiss 调用解决所有路径。
- 结果组件声明宿主语义：嵌入工作台内切换，独立任务详情向前打开衍生编辑。采用仍走现有领域命令，只有成功收据才更新镜头。
- 首版镜头审阅复用结果能力；从候选精确预览进入、采用固定版本、返回原镜头。完整镜头焦点页后续按实际复杂度拆分。

验收：项目→镜头→草稿→采用→返回镜头重复三轮，返回栈不增长；任务→修图→返回仍是原任务；Agent 外部视频预览一次返回离开预览，不先进入参数编辑；上下文删除与冷启动均可退出；顶部/硬件返回一致。

### P4：辅助页、项目选择及局部状态收口

拆成三个可独立交付的小包：P4a 项目/素材入口及返回文案；P4b 项目创建、选择、页签和精确计划/提案；P4c 设置往返、工具恢复与选择器目的。

落点：`CreativeHome`、`AgentWorkspace`、`AgentCreativePanel`、`agentCreativeActivity`、`CreativeWorkspace`、`ProjectPlans`、`ProjectActivityPanel`、settings route、`PromptAssistSheet`、`CreativeAssetPicker`、旧视频及草稿列表 routes。

- openSettingsFor 带来源与恢复表面 ID；配置草稿和保存结果明确，只有配置成功才显示可用。
- 重复相同参数仍作为新打开请求处理；恢复助手时保留未应用建议与输入，过期上下文重新校验。
- 项目页签恢复、提案定位与读取请求使用对象/请求身份防止旧异步结果覆盖新选择。
- 统一编辑保存出口，但不把“去设置修复配置”一律禁用；提交中可查看任务，已冻结输入不能被错误改写。

验收：从助手两次去同一设置分区并回到同一表面；两种来源新建项目正确落位；从两条提案分别进入可定位原对象；选择参考图/遮罩/采用版本文案与命令一致；所有无历史错误页面可退出。

## 5. 架构与新增能力如何落地

| 方向 | 决策 | 进入条件与最小交付 |
| --- | --- | --- |
| A4 服务边界 | 增量采纳 | P1–P4 触及的结果/来源查询先收口；新增功能使用命令/查询契约。架构测试保护新增边界，存量 SQL 分批清理 |
| A5 RuntimeAdapter | 近期小范围落实 | 对外收敛启动、取消、事件订阅、恢复状态；框架注册与 LangChain 转换留在适配层。不要同时改事件协议和存储格式 |
| A3 会话恢复 | 先如实呈现中断，保留已有任务恢复 | 持久业务步骤先于任意 Agent checkpoint；只有明确要求工具边界续跑时再验证 SQLite checkpointer |
| 上下文助手 | 有条件采纳 | 先解除 AgentScreen 卸载对全局运行的 disposeAll 影响，区分关闭 UI、取消运行、应用退出；验证多会话隔离后开放 |
| 本地技能库/快照 | 新能力第一批 | 本地文本/单技能包→兼容检查→不可变版本→显式绑定默认助手→新运行实际读取；同名不覆盖，失败无半安装 |
| Skill 提炼 | 技能使用闭环后实施 | 用户选择证据→模型生成草稿→审阅发布→独立启用；测试跨项目复用，不将一次生成成功当作方法有效 |
| AgentProfile | 先默认配置，后用户角色库 | 首版只满足技能绑定、工具集合和模型配置引用；避免与安装器同时扩成完整角色管理产品 |
| DeepAgents 升级 | 独立验证，未过门槛不进入生产 | 固定候选与关联依赖；解决 node:crypto 真实字节哈希、完整 Metro/Hermes、视觉/取消/事件/旧会话迁移；实验失败不阻塞技能应用层 |
| A2 编辑文档 | 按实际编辑器引入 | 先 SceneDocumentVersion + 静态摄影机/取景来源；Canvas/Timeline/完整 ShotPlan 轨道后置，不一次建立四套空实体 |
| 静态 3D 导演台 | 值得验证，有条件产品化 | 本地打包 WebView + Three.js 作为候选，离线摆场→保存重开→PNG→资产→现有草稿→返回镜头。原生 GL 作为失败后的替代验证 |
| A1 通用流程 | 当前两步保持，扩展前抽 handler | selection/video 行为等价后，加入一个真实第三步；有 3D 成果则 local.render，否则选已交付的结构化 agent 步骤，不为验证编造空 handler |
| A6 服务商能力描述 | 有真实第三服务商需求再推广 | 当前少量能力检查可集中；不为消除所有 AutoDL/NovelAI 分支进行抽象重写；必须用真实输入/输出/授权/恢复链验收 |
| 本地备份/资源治理 | 契约前移，界面分批 | 新增实体同步定义所有权、引用计数、导出清单、缺失文件与恢复；只备份 SQLite 不算完整备份 |
| 通用 SurfaceHost / 宽屏 | 小样本后推广 | 先助手与选材两种表面，证明键盘、返回、输入互斥有效；宽屏沿窗口尺寸验证，不照搬网页 CSS/Next.js 方案 |

**暂不实施：** Pi 全面替换、远端异步子 Agent、任意脚本技能执行、技能商店、无限画布首页、任意循环流程、无界多 Agent 并发、完整时间线/运镜/长视频编码。这些目前缺少必须由其解决的近期问题或设备证据。

3D 技术验证不应接入生产依赖后才做性能判断。记录目标设备、对象数量、拖动响应、帧时间、峰值内存、包体增量、导出耗时和 context 丢失恢复；预算依据基线与目标设备确定。没有设备数据不能宣称 WebView 路线达标。首版不承诺生成模型严格执行空间控制，也不宣称已有专用深度/控制视频输入。

技能首版绑定与运行快照同时落地：新运行固定版本，运行中发布不替换内容，权限撤销仍即时检查。ZIP 路径/大小/引用检查、脚本依赖标识及内置包只读属于安装器必要能力。多技能合集、复杂角色管理和高级检索可后续扩展。

流程推广须统一“全部必要步骤完成”判定、稳定业务命令身份、未知提交核查、人工节点与执行租约。attemptId 不能成为网络重试产生新消费的借口。旧两步计划保留可读/可恢复路径，禁止用新解析器将它们误判为已完成。
