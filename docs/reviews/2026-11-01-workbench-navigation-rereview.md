## 结论

**方向正确，上轮六项问题的主体修复可以认可；但目前仍不能认定页面和功能的组合流程已全部验收。** 本轮确认 5 项 P2，集中在“保存后真正生效什么”“新对象保存后落到哪里”“关联入口到底打开什么”。其中时间线另存后的旧对象操作、连接下思考强度被覆盖，应优先处理。

没有在本轮范围内确认新的 P1 消费授权问题。桌面执行端和远端 Worker 继续是禁止项；建议全部在 Android APK 内实现。外部模型和生成 API 不等于远端业务编排。本轮不重新进行竞品研究，依据是当前源码、上轮发现、实施方修复台账及独立验证。

## 必须处理的剩余问题

### R1 / P2：指定时间线另存后没有切换到新工程，合成仍操作原工程

源码：[TimelineScreen.tsx:51](../../mobile/src/creative/TimelineScreen.tsx)、[限定查询:27](../../mobile/src/creative/TimelineScreen.tsx)、[合成按钮:54](../../mobile/src/creative/TimelineScreen.tsx)。

从素材使用位置进入指定工程 A → 载入副本 → 改名称或片段 → 保存新工程快照。领域层已返回新 `timelineId=B`，页面却丢弃返回值、清除 dirty，再调用仍被路由参数 A 限定的 refresh。已保存工程区继续只显示 A；点击可见的“在本机合成”提交的是 A。新 B 确实保存了，但当前页面没有直达它的入口，“最新工程”仍查 A。若 A 已合成，新工程的合成还会被旧行状态挡住。

离线组件探针复现：保存 payload 为新名称，返回 B；无 push/replace、新行不可见；随后合成 payload 仍是 A。它不是数据库保存失败，而是成功后的对象定位失败。设备只查看了空时间线页面，没有创建或合成工程。

建议：消费 `timeline.create` 的真实返回 ID，在解除编辑保护后定位 B，或显式呈现新快照及“打开/合成该快照”。保留 A 的历史身份；不要让“最新工程”在指定工程模式中假装刷新全项目。

验收：指定旧工程另存 B 后，用户可直接看到并合成 B；视频版本、字幕与标题对应 B；返回素材来源仍能定位 A；普通项目列表进入的另存流程也不回退旧页。

### R2 / P2：显式连接下，用户保存的思考强度被读取层静默覆盖

源码：[storage.ts:57](../../mobile/src/settings/storage.ts)、[agentConfig.ts:14](../../mobile/src/agent/agentConfig.ts)。

设置页允许选择 low/high 等强度并显示保存成功；saveSettings 也确实写入 `llm.reasoningEffort`。但 readSettings 只要发现显式连接，就在最后强制叠加 `llmReasoningEffort:'default'`。Agent 配置随后消费这个覆盖值，因此用户保存的选择没有传入运行配置。该问题影响模型行为和预算预期，不只是显示不刷新。

离线真实存储探针：选择 `gpt-5.1` 显式连接 → 保存 low → 安全存储为 low，readSettings 却返回 default。没有调用模型。

建议：明确思考参数究竟属于连接还是运行偏好，设置页和 Agent 读取同一来源；切模型时校验兼容性。若某连接不支持修改，应隐藏/禁用相应控件并说明，不能保存后静默忽略。

验收：显式连接下保存受支持强度后，重新读取、重新进入页面和新运行 specification 均保持同值；更换不兼容模型时有明确处理。

### R3 / P2：设置保存后丢失展示用连接身份，返回连接管理也不刷新

源码：[settings.tsx:80](../../mobile/app/%28tabs%29/settings.tsx)、[validation.ts:11](../../mobile/src/settings/validation.ts)、[settings.tsx:52](../../mobile/app/%28tabs%29/settings.tsx)。

prepareSettingsForSave 返回的是归一化可编辑字段，不包含 llmConnectionId/revision/supportsImages；页面却用 prepared 整体替换 values 和 baseline。因此只改最大重试次数再保存，也会把“当前连接：ID”变成“当前使用旧版连接配置”。存储中的显式连接仍在，界面与真实状态不一致。离线组件探针确认 saveSettings 只收到重试字段，但页面随后误标旧版连接。

同一页面只在 mount/loadAttempt 时读取配置；进入连接管理选择新连接后返回，没有回焦刷新。页面还持续提供可编辑的旧地址/模型/密钥输入，而存储层已经要求到管理页修改；用户可能对着过时表单编辑，直到保存才被拒绝。

建议：把有效连接身份、只读连接摘要与可编辑偏好分开建模；保存偏好不能替换身份。返回管理页后刷新连接摘要，并保留尚未保存的偏好；显式连接下用统一管理入口替代无效可编辑字段。不要简单回焦覆盖整份表单。

验收：保存任意普通偏好后仍显示真实活动连接及能力；管理页 A→B 返回立即显示 B；存在未保存偏好时不丢输入；页面展示与下一次运行实际连接一致。

### R4 / P2：撤销连接永久占满配额，常规密钥轮换最终无法继续

源码：[llmConnections.ts:19](../../mobile/src/settings/llmConnections.ts)、[撤销:22](../../mobile/src/settings/llmConnections.ts)、[ModelConnectionsScreen.tsx:18](../../mobile/src/settings/ModelConnectionsScreen.tsx)。

新增按 items.length 限制 8 项；撤销只置 revoked 并增加 revision，仍留在 items 中。页面没有删除、替换、更新密钥或释放槽位的路径。正常更换凭据若采用“撤销旧连接→新增连接”，累计 8 次后即使没有任何有效连接也无法再新增。该生命周期缺口并非本轮六个修复提交新引入，但仍存在于当前版本。

离线真实存储探针创建并撤销 8 条测试连接后，第 9 条被“最多保存 8 个模型连接”拒绝。测试使用内存 SecureStore mock，没有写设备账号。

建议：支持显式替换/更新连接或清理已撤销连接。历史运行需要保留身份与撤销墓碑，但不应永久占用可配置连接名额或保留无用密钥。清理不能让旧 ID/revision 恢复授权。

验收：多轮轮换后仍能新增有效连接；旧运行继续拒绝已撤销凭据；清理不会隐式选择其他连接或绕过撤销。

### R5 / P2：项目封面使用位置传入不存在的页签，落点由历史状态决定

源码：[CreativeWorkspace.tsx:307](../../mobile/src/creative/CreativeWorkspace.tsx)、[页签恢复逻辑:154](../../mobile/src/creative/CreativeWorkspace.tsx)。

素材详情“使用位置”的封面项发送 `tab:'overview'`；项目组件只接受 brief/shots/assets/plans/activity。overview 被当作没有有效页签，随后恢复该项目的上次页签。于是点击项目封面可能打开镜头、素材或计划，而不是预期概览，也没有打开封面管理。

离线组件探针实际点击封面使用行，取得 overview，再把这个参数传给项目组件；最终选中镜头页签。没有修改项目封面。

建议：先明确入口意图：若目标是概览，发送 `brief`；若目标是封面管理，增加受支持的明确焦点。将 UsageEdge.kind 和项目页签收束成可穷尽处理的类型，避免继续以任意 string 直接拼接路由。

验收：无论上次停在何页，点击同一封面引用都到确定位置；普通项目收纳、镜头、设定、草稿、任务、时间线分别有点击落点契约。

## 页面树与交互设计判断

当前继续采用“主导航四入口 + 根 Stack 对象详情 + 项目内部五页签”的结构是合理的，不需要为这些缺陷再扩展主导航层级。问题主要发生在边的契约，已经不只是页面有没有入口。

应优先建立三种明确规则：

1. **对象定位**：项目/素材/版本/工程各有稳定 ID，别名和历史页签不能覆盖明确目标；保存新对象必须接住返回 ID。
2. **返回语义**：返回来源与返回项目是两个动作。时间线、媒体检查等仍有名为“返回项目”但仅 router.back 的实现；从素材详情进入时实际返回素材详情。建议按入口显示“返回来源”，另提供必要的项目落点。冷启动无历史时需明确 fallback；本轮未把未验证的冷启动情况算成已复现缺陷。
3. **编辑与配置刷新**：已有未保存 guard 应复用；focus 刷新只能更新适合刷新的有效状态，不能覆盖用户草稿。能力页已补 focus 更新，但设置页仍缺同样闭环。

内置 Skill 的“可见”已解决，接下来应改进可理解性。当前截图中的一条英文长描述、完整指纹及展开后的 meta.yaml/正文直接占据多屏；meta.yaml 已含中文展示名，却没有被提升为主标签。建议默认显示中文名称、一行用途、来源/版本和可用状态；技术指纹及完整文件进入详情。搜索应覆盖本地化元数据；运行记录可从摘要跳到对应会话/运行，并明确当前项目范围。此处是体验建议，未把它们混入上面的五项已复现缺陷。

不建议继续以“入口更多”衡量推进。下一轮交付重点应是完整旅程：进入指定对象 → 修改/授权 → 保存 → 找到新结果 → 检查实际生效值 → 返回原上下文。每条旅程至少覆盖一个跨页成功和一个失败/取消情形。
