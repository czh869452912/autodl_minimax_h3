# 视频任务恢复与统一账号设置

## 修复依据

- 手工视频使用 creative_accounts；旧编辑器、旧后台执行与下载地址刷新仍读 autodl.token，造成同一服务两套连接状态。
- 视频任务把参考素材保存为 asset:// 内容哈希，AutoDL 发送前却直接交给文件系统读取；本地读取错误被通用提交异常归为 UNKNOWN。
- 创作预算在读取素材前已经标记 DISPATCHED；未知任务又被任务中心传给旧任务的克隆重建入口，因此既阻塞工作区，又报资源或授权错误。
- 模拟器只读检查：AutoDL 和 NovelAI 账号记录仍在；现有一个 AutoDL UNKNOWN 任务没有远端句柄，其参考原件文件仍存在。

## 最终行为

1. 所有工作台的账号按钮进入设置 → 创作账号。旧 AutoDL Token 在安全存储中自动迁移；若已有统一账号，以现有账号为准并移除旧键。其他偏好保存不会写回旧 Token。
2. 新旧视频编辑器、后台提交与未绑定历史任务查询共用统一账号；已绑定任务的查询与下载刷新保持其原凭据代次，禁止换用默认账号。
3. 提交前验证凭据和原件；asset:// 只解析到对应 CAS 文件，校验哈希后编码。缺凭据或缺文件时不创建任务。
4. 后台发送前再次准备素材，完成后才跨越 DISPATCHED 边界。本地准备失败为 FAILED，释放 RESERVED；进程中断后有 RESERVED 证据的未发出请求也可恢复为失败并释放占用。
5. 已发送但没有取得确认的 UNKNOWN 不自动重发。任务详情提供按时间和描述核查、解释无法自动查询的原因、以及“已核查，解除本次等待”。用户确认只记录核查事件并解除当前工作区等待；原状态、素材、消费记录保留，后续生成仍需手动点击。
6. 创作任务的核查入口打开其专用详情；旧任务重建先检查账号和素材，失败不插入新的占位任务。
7. 未知结果的空画布显示“结果待核查”；没有远端句柄时不提供无效的同步按钮。

## 设置交互

- 首页只有“连接与能力”“使用偏好”两组紧凑列表，去掉重复大标题与旧工作流账号分类。
- 账号默认显示单行状态，展开后管理令牌；连接即时保存，不再出现多余的全局保存按钮。
- 助手、存储、播放保留草稿、保存和校验；复杂参数继续折叠。
- 工作流独立管理，展示名称与版本；不再承担账号绑定。
