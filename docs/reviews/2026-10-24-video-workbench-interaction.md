# 视频生成工作台交互梳理

评估基线：`192b1c6f`。以下保留调整前的分析与目标；已按认可的“准备优先”方案实施主要布局、工作流与草稿链路。实际完成项和验证边界见 [实施记录](2026-10-24-video-workbench-implementation.md)。本轮没有发送付费生成请求。

## 当前布局为什么别扭

1. **第一张参考图被当作主作品。** 它使用剩余区域的 `flex: 1` 铺满画面，动作描述只有底部 52 高度。参考图只是视频生成的输入之一，当前布局却让看静态图成为主要活动。多参考图时，第一张图的视觉权重还容易使人误认为它是首帧。
2. **输入与输出共用区域，却没有明确的状态边界。** 有素材或任务关联后改用结果区；没有结果时展示第一张参考图。用户修改参考素材或描述，容易混淆当前预览对应的是本次已提交任务还是下一次输入。
3. **配置入口表达错误。** 底部 `H3 · 768p横 · 5 秒 · 参考图 1` 看似整组设置摘要，点击却只管理参考图。设置同时隐藏了描述和预览，占据整页；参数不多时留下大片空白。
4. **选项组织沿用了接口格式。** 横竖方向与清晰度合并为四个值；常用时长和数字框重复常驻。用户应分别决定画面方向、清晰度和时长，提交时再映射为接口值。
5. **视频准备和视频审阅是两种不同活动。** 准备时要组织素材、动作和运镜；审阅时要播放、定位时间点、切版本并查看对应输入。压缩成图片页的“画布＋两行提示词”，两种活动都会受限。

## 工作流选择决定创作区的能力

工作区的结构应为：**工作流 → 对应的素材与描述 → 该工作流的常用参数 → 生成 → 结果**。工作流入口位于创作区顶部，当前名称用紧凑的一行显示，不占据大卡片，也不埋在高级设置里。服务商、模型和工作流只在确实可分别选择时分层展示，避免三个描述同一能力的选择器同时常驻。

### 如何选择

- 点击当前工作流展开底部选择面板。每项展示易读名称、用途、必要素材及关键限制；来源／版本在详情中查看。名称相似的工作流可以用服务商或用途区分，不以原始接口 ID 为主标题。
- 候选来自现有工作流目录，只把已接入手工工作台、能够输出视频、运行适配器和凭据可用、输入能够正确表达的工作流标为可生成。目录中的“已安装”不等于当前页已经支持。
- 对暂不可用的已安装工作流说明具体原因，提供对应处理入口；不让用户填完整页后才发现无法执行。导入、同步、版本启用与回滚仍在工作流管理中，不挤入生成主界面。
- 只有一个可用工作流时显示当前名称与能力详情，不提供空洞的单项下拉。多个可用项时才提供切换列表；数量较多再增加搜索或最近使用，初期不预置分类仪表盘。
- 新建时恢复上次使用且仍可用的工作流；打开已有草稿优先恢复草稿自身的工作流。原工作流缺失时保留草稿，说明恢复方式，不静默改成默认 H3。

### 切换时保留什么

各工作流分别保留输入与素材缓存。切回原工作流时优先恢复它自己的草稿；首次切入另一工作流时，只带入明确兼容的描述与字段，其他项按新定义初始化。

| 内容 | 切换规则 |
| --- | --- |
| 描述 | 按明确的提示词语义映射带入，目标不接收时保留在原草稿 |
| 时长、清晰度、比例 | 校验新定义的枚举、类型和范围；不支持时提示需重选或使用默认值，不能静默当作等价参数 |
| 参考图片／音频 | 检查类型、格式、角色和数量；超限或不支持的素材留在原草稿，目标输入不自动截断或丢弃 |
| 首帧／尾帧 | 只有目标工作流明确声明角色时才展示；不能从普通多图输入推断 |
| Seed 与专属参数 | 留在各自工作流配置中；不假设跨引擎同值具有相同意义 |
| 项目／镜头 | 保持创作归属；输出仍由用户明确选择是否采用 |
| 已提交任务 | 固定原工作流、版本、输入和素材；切换仅影响下一次创作 |

兼容切换不弹全屏确认；就地显示简短变更摘要，并可撤销切换。确实需要覆盖尚未保存内容、替换工作流版本或明确裁减目标输入时，再在对应动作上解释变化。遇到保存或切换失败，恢复原工作流与原输入。

生成中的下一次创作可以选择其他工作流，但本轮仍维持当前工作区一次实际提交的规则。结果页显示产生该结果的工作流，不能跟着下一次输入的选择一起改变。跨工作流尝试保留在同一创作脉络中，版本明确标注来源；不要仅因切换工作流就把历史结果移走。底层可以使用不同草稿／素材记录和关联实现，不要求强塞进同一个底层草稿。

### 表单随能力变化

共同部分继续采用参考素材、描述和常用参数的紧凑结构。具体控件、上下限、可选项、必填项、媒体格式和默认值来自选定工作流定义。只显示该工作流真正接收的字段；模型特有控件按需展开。对尚无专属布局的兼容工作流，复用现有通用字段渲染，并把不能可靠表达的能力标为未接入，不能伪装成 H3 参数。

时长并非所有工作流都有，清晰度和比例也未必能独立映射。H3 的三个快捷参数是 H3 的展示适配，不是所有视频工作流必须具备的固定栏位。把常用项放到主界面需要明确的展示语义；现有 JSON Schema 和 `ui.sections` 负责有效性与分组，不能凭字段名称猜测业务含义。

### 当前代码差距

旧通用编辑器已通过 `catalog.listActive()`、`canonicalInputs()`、`alignWorkflowInputs()` 和媒体约束处理工作流选择、切换与动态输入，可复用这些基础能力。

新手工视频路径仍有这些固定绑定：`draft.createVideo` 写入 H3、`videoDraftInput` 限定 H3 参数、`draft.replaceInputs` 只接受最多 9 张图片、准备与提交固定 AutoDL 且音频为空、近期分组把同一素材的所有工作流视作一组而未表达跨工作流来源。它们需要随工作流选择一起调整，包括草稿格式、输入持久化、媒体角色和提交验证；只加一个选择器会导致界面选项与实际请求不一致。

草稿需记录工作流 ID、版本、内容标识及按该定义保存的输入。版本更新后提供明确的对齐摘要和恢复路径；提交时验证所用版本，历史成果始终保留原版本记录。不同版本不应伪装成多个独立工作流选项。

## 建议采用：准备优先，创作与结果为同一工作区的两个视图

保留图片／视频及手工／Agent 的现有模式结构。视频内部只在已经有任务或历史成果时显示轻量“创作／结果”切换；首次空白创作不显示无用的结果视图。切换只改变本地视图，保留同一草稿、任务与版本上下文，不创建新页面。

窄屏采用此结构；较宽屏幕可以把结果和输入并列展示，共享同一份状态。不要额外增加“上传、配置、确认、生成”的步骤向导。

### 创作视图

从上到下：

- **当前工作流**：紧凑名称入口，选择与详情按上述规则展开。
- **参考素材**：小缩略图横排和添加入口，无图时为一行添加操作。点击查看大图；管理面板支持导入、素材选择、替换、移除和顺序调整。第一张参考图不再铺满页面。最多 9 张按当前接口约束显示为上限，不一次展示 9 个空槽。
- **动作与运镜**：主要编辑区域，默认约 4–6 行，可展开。提供“主体发生什么、镜头怎么运动、希望保留什么”的简短空白提示，填写后消失。维持一个自由文本描述，不强制拆成多张表单。助手紧邻此处，应用建议可撤销，不代为生成。
- **常用参数**：随工作流变化。以 H3 为例，一行紧凑选择 `横屏／竖屏`、`768p／480p`、`5 秒`。每个值直接打开对应选择，而不是统一跳转到参考图管理。常用时长为 5／10／15 秒，只有选择“自定义”时出现 1–15 秒输入。Seed 放在“更多设置”，默认随机。
- **底部执行区**：保留单一“生成 5 秒视频”操作及保存／任务／费用状态。空描述在就地提示或禁用生成，不等到提交后才显示底层错误。不新增逐次确认弹窗。

整段创作内容可以滚动；键盘出现时让描述继续可编辑，收起无关的底部导航或减少其占位。返回优先收起键盘和面板，再离开工作区。

### 生成中

默认切到本次任务的结果视图，展示真实的排队／生成／下载状态和已提交的只读摘要，不显示虚构百分比或预计时间。

“准备下一次”回到可编辑输入。明确显示：当前任务内容已经固定；这里编辑的是下一次输入。等待完成前不能提交新请求，不隐式排队。离开页面后任务仍可恢复。

完成时，如果用户正在结果视图，则显示播放器；如果用户正在准备下一次，则保留输入和焦点，仅更新结果提示，不强制切页或覆盖草稿。失败提供原因与处理入口，UNKNOWN 优先核查原任务，不能当作可重复生成的普通失败。

### 结果视图

播放器成为主体，维持视频原比例，支持播放／暂停、进度定位、静音、全屏。下方显示简短时长、画面方向、清晰度和版本；版本列表用封面与时长识别，点击才切换播放源。

结果操作以保存、用于当前镜头和“调整后再生成”为主。最后一项返回创作视图，**只切回编辑，不立即再次提交**。查看本次参数始终读取对应任务的不可变快照；查看历史版本不能悄悄覆盖当前待提交输入。显式“复用该版本配置”才应用，提供撤销。

若播放器已有基础播放能力，则复用并检验其容器尺寸、版本切换和全屏返回，不重复实现播放器。参数差异比较可以从版本菜单进入，不长期占据主页面。

## 状态规则

| 用户情境 | 主要内容 | 主要动作 | 需保留的内容 |
| --- | --- | --- | --- |
| 首次创建 | 素材入口、描述、三个常用参数 | 生成所选时长的视频 | 输入自动保存 |
| 已有结果，准备下一次 | 编辑输入，结果通过轻量切换访问 | 生成 | 旧结果和当前输入分别保留 |
| 等待任务 | 真实状态、提交摘要 | 准备下一次 | 已提交快照不可变 |
| 等待时编辑 | 下一次描述和素材 | 等待本次完成 | 原任务继续跟踪，修改不影响它 |
| 审阅成果 | 播放器、版本和保存／采用 | 调整后再生成 | 返回创作不丢输入 |
| 结果未知 | 原任务和核查入口 | 核查原任务 | 禁止自动重发 |

## 能力边界

- 当前 H3 手工路径实际提供自由文本、方向／清晰度、1–15 秒时长、Seed 和最多 9 张参考图。参考图是普通参考输入，当前定义没有首帧、尾帧或多镜头时间轴字段，界面不能据此承诺这些控制。
- 本地工作流定义虽然有最多 3 个音频输入，但手工创作的准备与提交目前传入空音频数组。这是能力接入缺口；仅在界面增加“添加音频”不能完成支持，需要引用存储、快照、提交、恢复和测试一并接通。本次版式调整不预设其已经可用。
- 横竖方向、清晰度分开显示后，仍要准确映射回现有四个接口值，不改变请求语义。方向变化不代表对参考图进行破坏性裁剪。
- 费用没有可靠估算时继续明确说明无法估算，不根据分辨率或会员状态推测。

## 落地优先级与验收

**先接通工作流与草稿能力**：复用目录和输入对齐能力，完善草稿版本及媒体持久化。验证实际请求来自所选工作流，切换与恢复不会丢失输入，不把未接通的候选标为可用。

**再调整输入布局**：移除首张参考图的全屏占位，扩大描述，拆分该工作流的常用参数，修正摘要入口归属，设置改为就近面板。首屏应能看见当前工作流、参考素材状态、主要描述和生成动作。

**再明确结果状态**：创作／结果共享工作区，生成中显示固定的本次输入，完成后不打断下一次编辑；结果页区分查看参数与复用参数。重点验证生成前后与多次生成的状态切换。

**最后打磨视频审阅**：播放器尺寸、进度、全屏、封面版本选择、镜头采用和参数比较。宽屏可并列，窄屏按当前视图聚焦。

验收需覆盖无参考图、1 张／9 张参考图、长描述、键盘、竖图配横屏输出、生成时修改下一次、切换历史、UNKNOWN、播放失败、全屏返回和大字体。图像生成的重复确认弹窗不应重新引入视频页。

另外覆盖多工作流来回切换、媒体不兼容、参数超限、工作流缺失／禁用／升级、切换保存失败，以及生成中的工作流与下一次输入工作流不同。当前内置定义只有 H3 一个工作流 ID 的多个版本，不能据此声称已验证多个真实工作流；多工作流状态需要专门准备有效的已接入定义和测试。

本轮产出两种可切换状态的布局示意，偏好“准备优先”；另一种“预览与输入同屏”供比较。前者更适合窄屏，后者对反复对照结果更直接，但会进一步压缩长描述的空间。
