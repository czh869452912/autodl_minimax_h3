# App 产品与交互设计对标评估

日期：2026-10-24  
代码基线：`c0292ee7`  
评估方式：当前源码、仓库已有 Android 模拟器截图及验收记录、外部产品与项目官方文档。本文没有重新操作模拟器，也没有运行真实账号生成；外部产品的行为依据文档，未声称亲自试用。优先级表示体验改进顺序，不表示已发现对应严重程度的软件缺陷。

## 1. 核心判断

目前已经具备不少可靠的业务基础：草稿留存、自动保存、冲突保护、镜头与素材关联、任务恢复、成果版本和项目采用关系。主要短板在于：这些能力还没有被组织成自然、直观、连续的创作体验。

“毛坯房感”主要来自四件事：

1. **页面更像表单与操作目录。** 标题、说明、字段、展开按钮逐项向下排；开始创作、调整参数、查看成果缺少一个稳定的工作空间。
2. **用户需要理解太多内部对象。** 草稿、任务、素材、版本、默认版本、项目固定版本、镜头采用版本都有合理的数据含义，但页面让用户频繁切换这些概念。
3. **视觉语言单一。** 类型选择、展开设置、导航、普通操作经常都画成同样的描边圆角按钮。颜色统一了，控件的用途和重要程度没有充分区分。
4. **完成一次生成后，继续创作仍有断点。** 已有原页结果与“继续修改”等入口，但部分操作建立新草稿并切页，授权后还要再发一句话，视频与版本也缺乏充分的视觉识别。

建议产品方向：**以作品为中心的移动创作工作台，项目用于组织，助手用于协作，任务系统提供进度与恢复。** 现有“创作 / 项目 / 素材 / 助手”四个一级入口可继续保留；先提升入口内的工作方式。

此前 `2026-10-24-creative-ux-maturity.md` 证明了多项流程保护已实现，并明确保留真实账号验收条件。这些成果应继续保留；但“防止丢输入、能找到下一步”只能证明基础可用性，不能单独证明产品交互已经成熟。本次评估补充的是操作效率、内容呈现和创作连续性。

## 2. 对标对象与可迁移做法

以下“本项目应用”属于设计建议；不意味着相关产品支持本项目的供应商、数据结构或移动端运行方式。网页布局应改写成适合手机的交互。

| 对标 | 官方文档确认的做法 | 本项目应用 | 适用边界 |
| --- | --- | --- | --- |
| [Runway：生成与迭代](https://help.runwayml.com/hc/en-us/articles/46974685288467-Creating-with-Gen-4-5) | 描述与参数配置后生成；在成果上收藏、下载、继续使用并迭代 | 工作台以预览为核心；直接修改描述、再生成、用于镜头或制作视频 | 学习生成循环；不照搬模型参数、价格或网页侧栏 |
| [NovelAI：基础创作](https://docs.novelai.net/en/image/basics/) | 从提示词到选择结果，再修改、变体或增强；提供标签建议与输入容量提示 | 提示词编辑支持明确的输入反馈；常用选项就近调整；高级参数渐进展开 | 标签建议和容量提示须有词库及模型限制依据，不能用字符数伪装 token 数 |
| [InvokeAI：图库与作品复用](https://invoke.ai/features/gallery/) · [源码](https://github.com/invoke-ai/InvokeAI) | Boards 组织作品；从作品恢复提示词、种子或完整参数；结果可转入后续创作 | 素材详情先看作品，再“复用参数”“制作视频”“用于项目”；参数来源可追溯 | 不需要引入桌面画布或完整节点编辑器 |
| [Immich：检索](https://docs.immich.app/features/searching/) · [源码](https://github.com/immich-app/immich) | 可按媒体类型、相册、时间等过滤，并具备语义检索 | 先做好图片与视频封面、项目/类型筛选、快速浏览；后续再评估语义搜索 | 首轮不引入机器学习服务，名称与结构化筛选先解决实际问题 |
| [Open WebUI：Artifacts](https://docs.openwebui.com/features/chat-conversations/chat-features/code-execution/artifacts/) · [源码](https://github.com/open-webui/open-webui) | 对话中的独立成果可在专门区域查看、编辑和切换版本 | 助手中的方案、草稿、候选结果可独立打开，并能返回原会话继续讨论 | 参考成果与对话的关系；不把网页 HTML artifact 引擎搬进 RN |
| [ComfyUI：界面分工](https://docs.comfy.org/interface/overview) · [前端源码](https://github.com/Comfy-Org/ComfyUI_frontend) | 工作区、参数、素材、运行控制分工；运行区提供活动任务入口；App Mode 提供线性运行方式 | 区分内容区、参数区和运行反馈；任务入口显示活动状态；旧工作流保留专用入口 | 手机主流程采用线性工作台；节点图是专业场景的独立取舍 |

最值得先吸收的组合是：Runway 的生成循环、InvokeAI 的作品复用、Immich 的媒体浏览、Open WebUI 的成果独立呈现。

## 3. 当前差距：按源码核实

### 3.1 首页要求用户先经过一层准备页

依据：`mobile/src/creative/CreativeHome.tsx:46`、`:53`、`:60`。

首页输入描述后点击“进入图片/视频工作台”，创建草稿并切换页面；接着在工作台处理参数与提交。这种结构可以理解，但常规路径上多了一层“先填描述，再进入编辑”的过渡。首页最近草稿以状态、两行提示词和按钮呈现，缺少成果缩略图。

建议首页重点承接“新建”和“继续”：新建直接打开工作台并聚焦描述输入；可保留快捷输入作为可选入口，输入后必须原样转交。继续区显示封面、项目/镜头、最近状态，点击整行继续。首次空态给两三个可编辑的示例，点击只填入草稿。

### 3.2 工作台仍由长表单主导

依据：`ImageDraftScreen.tsx:65`、`:79`、`:93`，`VideoDraftScreen.tsx:118`、`:129`、`:133`；截图 `image.png`、`video-review.png`。

图片页已经有固定生成栏，提交后也已经在页面上方显示结果，不能将其描述为“完全没有原页成果”。差距在于编辑中、生成中和完成后还没有稳定的整体布局：视频参考图位于描述和参数之后；多张参考图逐张占用大块垂直空间；设置展开会继续拉长页面；图片页提交后的固定按钮统一变成“返回资产库”。

建议建立同一个工作台外壳：顶部紧凑对象标题与保存状态；中部预览/参考图/候选；下部描述和常用参数；底部根据状态变化的主操作。首次无图时只放简短占位，避免巨大的无内容画布挤走输入。视频页先显示参考图及其用途，再编辑动作与运镜；参考图用缩略条并可展开排序。

### 3.3 不同用途的操作画得过于相似

依据：`mobile/src/ui/ListPageUI.tsx:5`、`:16`，`mobile/src/creative/creativeUI.ts:3`。

`ListAction` 主要只有实心与描边两类。工作台用描边按钮表示比例、展开设置、返回、移除等多种动作，部分选择还通过文字前缀“✓”表示。统一组件降低了实现成本，却没有充分表达语义。

建议分别提供主按钮、文本操作、设置行、单选分段、筛选标签、图标按钮。比例选择用比例图形与数值，模型和时长用摘要设置行；展开区有箭头和当前值。每个决策区域保留一个主动作。保持约 48dp 可点区域，通过压缩无效间距和减少边框获得密度，不依靠缩小字体与触控区。

### 3.4 素材浏览的视觉基础不完整

依据：`mobile/src/creative/AssetTile.tsx:9`、`:11`，`CreativeWorkspace.tsx:199`。

素材卡目前仅对 image MIME 绘制预览，视频卡没有对应封面。列表通过 ScrollView 中的 map 渲染，卡片各自查询版本。素材量增加时，存在集中读取和渲染的性能风险；本次没有做性能实测，不能据此给出掉帧结论。

建议统一封面模型：图片缩略图；视频封面、时长和播放标识；音频与文档有明确类型占位。首轮支持“全部 / 图片 / 视频”和项目范围；详情优先全屏预览、版本缩略条、继续创作。大列表使用虚拟化和稳定尺寸、批量加载封面摘要，读取失败有占位和重试。

### 3.5 版本功能暴露了过多内部信息

依据：`VersionComparison.tsx:18`、`:20`、`:25`，`CreativeWorkspace.tsx:161`、`:182`、`:190`。

已有版本比较、差异字段和版本固定能力。但比较界面先选择“版本 N”，随后显示字段路径、状态值与最多 20000 字符的 JSON 参数；窄屏顺序查看两个图，不方便回答“哪个结果更好”。

建议先选两个缩略图，提供同位置 A/B 切换，图片可后续增加拖动比较。差异摘要先显示“描述变了 / 比例变了 / 种子变了”，完整参数放“技术详情”。明确三种范围：素材默认版本、项目使用版本、镜头采用版本；修改前用项目/镜头名称解释影响范围，不能把三者合并成一个全局“采用”。

### 3.6 助手授权与继续执行之间存在明确断点

依据：`AgentCreativeCards.tsx:64`、`:70`，`AgentCreativePanel.tsx`。

用户授权后，界面提示再发送“按当前草稿继续”让助手执行；“编辑这份草稿”与项目授权并列。用户已表达允许继续，却仍要自己补齐执行动作。

建议在明确展示项目、操作对象、供应商、请求次数、费用状态和有效期后，提供“授权并继续本次操作”；确认后触发可追踪的继续事件，卡片直接进入执行状态。取消保持待确认。需要增加运行时续执行契约、幂等和授权范围校验，不能只把现有授权按钮改个名字，也不能将项目级授权误标成草稿专属授权。

保留独立助手入口，同时在工作台提供“帮我改描述/规划运镜”，携带当前对象；助手建议应能预览、修改并应用，返回时保留原工作台。

### 3.7 全局导航与设置占用注意力

依据：`mobile/app/(tabs)/_layout.tsx:13`，`DraftHeading.tsx`，截图 `settings-mature.png`。

四个主入口已经收敛，值得保留。当前每个一级页顶部都铺“任务中心 / 设置”文字链接，随后还有页面大标题，纵向空间利用偏低；进入隐藏于底栏的设置/任务页时，底栏没有相应选中项，位置关系也需要表达。

建议一级页采用统一紧凑 AppBar：页面标题、任务状态入口、设置图标。任务入口显示运行数与需处理提示，数字与状态必须来自真实数据。任务与设置使用明确的辅助页面导航/返回关系。设置页采用“账号 / 助手 / 存储 / 高级”的设置行与独立详情页，账号详情显示已保存、已验证、连接异常等可区分状态。

### 3.8 项目有状态驱动的下一步，但还缺少视觉制作视图

依据：`ProjectOverview.tsx`、`ProjectShots.tsx`。

镜头已能根据已有草稿、已提交任务和采用结果决定主动作；不能再把“每次点击都新建草稿”作为当前缺陷。现在仍以卡片标题、说明和按钮为主，多个镜头的画面、先后关系、待审阅项不容易一眼看清。

建议默认显示分镜列表：序号、缩略图、镜头名、时长（如已知）、状态和下一步。提供“全部 / 待出图 / 待视频 / 待采用”筛选；轻量排序有可发现的按钮，拖动可作为增强。先做好镜头浏览与候选采用；时间轴剪辑是更大产品范围，应另立需求。

## 4. 建议的主流程与页面结构

### 图片创作

```text
创作 → 新建图片 → 工作台写描述/调比例 → 确认本次生成
                                      ↓
                  同一工作台：生成状态 → 候选结果
                                      ↓
              修改描述再生成 / 制作视频 / 用于镜头 / 导出
```

“再生成”在数据层可以创建新草稿和任务，但用户仍留在同一个可恢复的创作会话里；每次结果与输入快照可追溯。不要为保持原页而修改已提交快照。

### 视频创作

```text
从图片点“制作视频” → 工作台自动带入图片与项目/镜头
                  → 写动作与运镜 → 调比例/时长 → 确认生成
                  → 同页播放 → 采用 / 调整再生成 / 导出
```

### 工作台结构示意

```text
‹  镜头 02 · 视频创作           已保存  ⋯
星夜短片

当前图片 / 视频预览
候选缩略条：参考图、当前结果、历史结果清楚区分

动作与运镜                         助手完善
[输入描述……]

横向 16:9     5 秒     标准画质      更多

底部：当前状态、真实费用或费用未知说明
主动作：按下表随状态变化
```

这是结构草图，不是已完成的高保真方案。键盘打开时优先保证编辑区与主操作可达，预览可压缩；大字号允许换行和滚动。

## 5. 统一状态与主操作

| 状态 | 页面应呈现 | 主操作 | 交互要求 |
| --- | --- | --- | --- |
| 可编辑 | 已保存/保存中，当前参数摘要 | 生成图片/视频 | 缺必填条件就近解释；连接账号后回到原输入 |
| 待确认 | 输入、供应商、次数、费用状态、授权范围 | 确认并生成 | 用可阅读的确认面板替代内部凭据编号和 Seed 主导的提示；技术字段可展开 |
| 提交中 | 正在提交本次请求 | 暂不可重复提交 | 立即显示反馈，保留草稿；取消能力以执行器真实能力为准 |
| 排队/运行 | 当前阶段、最近同步时间 | 可离开继续其他创作 | 没有真实百分比/ETA就不显示；任务入口保留可见状态 |
| 完成 | 当前结果、候选数、采用状态 | 独立创作为继续修改/导出；项目创作为采用 | 按进入目的设置主操作，避免所有页面都默认“返回素材库” |
| 部分完成 | 可用成果与失败项并列 | 查看可用成果 | 明确哪些项失败；重试须区分重新生成和重新下载 |
| 失败 | 面向用户的原因与恢复建议 | 修复后重试或恢复下载 | 保留输入；涉及新消费则重新确认 |
| 结果不明 | 正在核查原任务、最近查询结果 | 核查原任务 | 不把未知当失败，不通过普通重试重发生成 |
| 导出中/导出失败 | 保存队列或权限问题 | 查看保存状态/重试保存 | 与“生成成功”独立表达，不要求用户重新生成 |

当前已经实现其中若干状态与恢复保护，本表作为跨工作台、任务中心和助手卡片的一致性契约。

## 6. 实施顺序与成本

成本是相对复杂度，不是工期承诺：小=局部呈现；中=跨页面组件/查询；大=跨服务、持久化与执行状态。

| 批次 | 内容 | 用户价值 | 成本与依赖 |
| --- | --- | --- | --- |
| 第一批，P0 | 图片/视频统一工作台外壳、常用参数摘要、参考图缩略条、状态主操作 | 降低每次生成的操作与理解成本 | 中；复用已有草稿、结果、任务服务 |
| 第一批，P0 | 图片/视频封面卡、最近创作缩略图、成果优先的素材详情 | 能认出、找到、继续自己的作品 | 中；封面生成/缓存、摘要查询 |
| 第一批，P0 | 控件语义拆分、紧凑标题栏、减少重复大按钮 | 全局层级更明确，释放手机屏幕空间 | 中；先定义组件再迁移核心页 |
| 第二批，P1 | 工作台内的迭代历史、A/B 比较、人话参数差异 | 生成后能快速判断与改进 | 中至大；持久化创作会话关系须先明确 |
| 第二批，P1 | 助手“授权并继续”、建议预览应用、对象上下文返回 | 消除对话与手动操作之间的断点 | 大；续执行契约、幂等与范围校验 |
| 第二批，P1 | 分镜列表、待处理筛选、就地候选采用 | 多镜头制作更有连续性 | 中；复用已有镜头关系 |
| 第三批，P2 | 预设收藏、结构化搜索增强、平板适配与克制动效 | 提升高频与进阶效率 | 中；依据前两批使用反馈推进 |

第一批建议按“工作台 → 媒体卡与素材详情 → 首页和全局导航”完成一个垂直样板，再扩展到项目和助手。设计系统先服务真实页面：AppBar、PrimaryButton、TextAction、SettingRow、SegmentedControl、MediaCard、StatusBanner、ParameterSheet。保留现有色调即可，字号、间距、边框和状态语义需系统化。

## 7. 验收方式

把以下任务作为后续原型和实机验收脚本。本次未执行用户实验，下面是建议目标，不是现有测量结果。

1. **初次出图：** 未建立项目也能开始；配置缺失时说明缺哪项；配置后原输入不丢。确认生成前准确看到供应商、请求次数与费用是否可知。
2. **生成后微调：** 看结果、改描述、确认再生成在一个工作台完成；不必先去素材库找刚刚的结果；旧结果仍能恢复。
3. **图转视频：** 当前图片在一次“制作视频”操作后带入；项目与镜头关联保留；能清楚确认参考图与输出比例。
4. **离开再回来：** 排队中退出，重新打开回到同次创作；显示真实状态且不重复消费。失败、未知和下载失败各有正确动作。
5. **候选采用：** 在多个结果中选中 B，用于镜头后，清楚显示该镜头采用 B；更新素材默认版本不静默替换镜头。
6. **助手接管：** 建议可先审阅再应用；授权确认后本次操作自动继续，取消不执行；切项目或换账号后原授权不能错误使用。
7. **素材查找：** 在 100/1000 项测试库中，图片与视频都能凭封面识别；项目/类型筛选有正确结果与空态；记录列表滚动与封面加载数据再决定性能门槛。
8. **移动适配：** 360dp 常规宽度、1.5 倍字体、键盘展开、系统返回均验证；主操作与错误可达，不能用压缩可点区域掩盖布局问题。

建议邀请 3—5 位未参与实现的用户做形成性测试，记录完成率、错误跳转、犹豫点、恢复成功率；点击数单独记录，不能把减少确认次数当作唯一优化目标。真实生成、下载、导出权限和助手恢复仍需配置测试账号后验收。
