# NovelAI 与 Agent 统一创作：UX/UI 正向设计方案

日期：2026-10-24。状态：设计提案，未实施界面改动。

本轮依据当前源码核对交互结构，不把旧设计文档的目标当作已实现功能；未运行新版 App 做真机视觉验收，也未开展用户访谈。以下问题是源码可确认的结构问题，使用效率判断及验收阈值是待验证的设计假设。

## 1. 产品定位与设计目标

用户来这里完成一张图、一个镜头或一个项目。NovelAI、H3 和 Agent 是完成这些目标的能力。页面首先回答四个问题：我正在做什么；已经做到了哪里；眼前需要我决定什么；下一步怎么继续。

产品组织原则：**以创作对象组织工作，以成果推动下一步，以 Agent 协助完成同一份创作。**

三类主要任务：

1. 快速出图：有一个画面想法，希望马上获得可查看、可修改、可保存的结果。
2. 项目制作：围绕统一设定组织角色、场景、镜头，逐步确定图片和视频成果。
3. 委托创作：告诉 Agent 目标，在关键节点审阅、选择、调整，并随时手动接管。

共同闭环：表达意图 → 准备草稿 → 生成 → 审阅 → 采用或修改 → 继续制作或导出。创建项目不是快速出图的前置条件。

## 2. 当前结构问题与证据

| 当前实现 | 对用户的影响 | 设计调整 |
|---|---|---|
| `CreativeWorkspace.tsx` 在同一 ScrollView 中切换项目列表、简报、镜头、资产详情；页头重复提供项目/资产/任务/设置跳转 | 页面边界不明确，返回和当前层级难以理解 | 项目列表、项目详情、资产详情使用独立路由和标题栏 |
| `app/(tabs)/create.tsx` 在旧 `CreateForm` 上方追加 NovelAI 和草稿入口；`app/index.tsx` 默认跳到该页 | “创作”看起来仍是视频表单，图片像附加功能 | 创作首页先选图片/视频；继续草稿在同一入口可见 |
| `ImageDraftScreen.tsx` 把全部版本预览放在表单之前；角色编辑常显，比例与模型在高级参数中 | 版本越多，修改距离越长；低频控件先于常用决策出现 | 当前结果 + 缩略图组；比例常显，角色按需添加，高级参数折叠 |
| 图片和视频草稿嵌入完整 `CreativeAccountPanel`，已绑定仍显示令牌和断开操作 | 每次创作都被账号管理打断 | 已连接显示一行状态；管理收进设置；缺失时在当前流程连接后返回 |
| `AgentCreativePanel.tsx` 把项目选择、次数授权、最近命令回执合并在折叠面板 | 用户先学内部机制，才知道如何让 Agent 做事 | 项目范围常显；授权随具体计划出现；结果以业务卡片进入时间线 |
| `ProjectShots.tsx` 用文本版本列表选图，镜头卡并列编辑、选图、选视频、建草稿、排序、删除 | 用户看不见要选择的图，也不知道下一步 | 缩略图选材；按镜头阶段给一个主操作，其余进入详情或更多 |
| `ProjectPlans.tsx` 要求用户选镜头、读取候选、勾选版本、保存计划 | 内部计划编排成本转嫁给用户 | 在镜头中点击“选图制作视频”自动准备选择流程 |
| 资产详情按每个版本展开项目加入/固定/封面等操作 | 随版本数和项目数增长，操作量膨胀 | 先选版本，再针对当前版本显示动作；项目用搜索选择器 |
| 多个“查看任务”入口都跳到全局任务列表 | 用户必须再次寻找刚刚执行的工作 | 定位到具体任务；从任务返回对应草稿、镜头或结果 |

保留已经有价值的实现：手动与 Agent 共用命令服务、版本不可变、采用显式发生、草稿自动保存、未知结果不自动重发。调整的是用户接触这些机制的方式。

## 3. 信息架构

建议底部导航：**创作 / 项目 / 素材 / 助手**。沿用现有四入口规模，调整顺序、命名和职责。避免增加一个重复首页，也不强迫所有操作经过聊天。

```text
创作：图片 / 视频 → 编辑 → 结果审阅 → 修改、采用、继续制作
项目：最近项目 → 项目概览 → 镜头详情 → 参考图 / 视频成果
素材：图片 / 视频 / 文本等 → 素材详情 → 版本与使用位置
助手：会话 → 当前项目 → 计划、草稿、选图、结果卡

一级页面公共入口：任务中心（运行/待处理） · 设置
二级页面：返回 · 当前对象标题 · 更多
```

- “创作”负责开始和继续；“项目”负责组织；“素材”负责寻找和复用；“助手”负责沟通与委托。
- 任务中心是后台进度和异常处理入口。正常生成可在原页面看结果，不以跳转任务中心为必经步骤。
- 草稿归入创作首页的“继续创作”，不形成第五个主模块。
- 历史视频在素材库统一呈现；迁移未完成时保留“历史作品”次级入口，旧路由继续可访问。
- 项目上下文使用明确标题，如“星夜短片 / 镜头 02”；未关联时写“个人创作”。不偷偷继承别的项目。
- 首次默认进入创作首页；已有工作通过“继续上次创作”恢复。进程恢复不自动重新发起生成。

## 4. 关键页面设计

### 4.1 创作首页：让用户马上开始

首屏包含图片/视频模式、一个主要输入区、一个主按钮，以及最近草稿。没有令牌管理、模型参数墙或项目创建表单。

图片入口默认使用当前适配器支持的预设；“让助手完善描述”是可选辅助。视频入口允许描述镜头和选择已有参考，参考要求由实际工作流决定。

快速出图无需项目，草稿和结果仍自动留存。项目选择为可选上下文，不阻塞第一张图。空态提供两条示例意图，点击填入输入区，不自动消费。

### 4.2 图片工作台：编辑与看图形成短循环

```text
‹  图片创作                       已保存  ⋯
个人创作 / 项目名·镜头名

               当前结果预览
              （首次为简短空态）
          候选缩略图 / 查看全部

画面描述
[用户的原始描述或提示词                 ]
让助手完善

横图 16:9   ·   当前模型   ·   1 张
+ 角色                         更多设置

NovelAI 已连接             费用暂无法估算
                   [生成 1 张]
```

信息分层：

- 常用层：描述、比例、模型摘要、生成数量。当前请求固定为一张时显示“1 张”，不放无法生效的数量选择器。
- 按需层：负面描述、角色、支持的参考方式；已有内容以摘要提示，不能折叠后失去可发现性。
- 专业层：采样器、步数、引导强度、Seed、自定义尺寸、角色精确坐标。Seed 可显示“随机/固定”，数值进入专业层。
- 角色配置进入专门编辑页，列表展示名称和摘要；位置用画布控件并保留数值编辑。只在当前模型支持时出现。
- 新用户使用比例预设，不直接要求输入 64 倍数；专业用户仍可设置合法尺寸。

结果出现后进入审阅状态，主操作根据目标改变：项目中为“用于此镜头”，个人创作为“保存到相册”。“继续修改”“制作视频”作为次操作。内部自动留存与导出到相册使用不同文案。

选择结果时显示版本和用途；“制作视频”默认只是引用此图建立视频草稿，不暗中改变项目默认或镜头采用关系。若同时采用，按钮明确写“用于此镜头并制作视频”。

点击生成时内部完成保存和预检，不要求用户先点“保存修改”再点击同一位置生成。保存失败停在本页，保留输入和可见错误；连点只产生一次提交。

### 4.3 项目工作台：从进展而不是简报表单开始

项目列表：封面、名称、最近更新时间、简短进展（如“2 个镜头待选图”）。新建项目为独立轻量流程，只要求名称；简报可稍后补充。

项目详情默认“概览”，内部入口为“概览 / 镜头 / 素材”。简报在概览中以摘要展示，点击编辑；活动记录放更多菜单或展开区。

概览顺序：

1. 项目目标与当前阶段。
2. 需要你处理：选图、确认修改、解决阻塞；无待办时隐藏。
3. 继续制作：最近镜头或草稿，以及一个明确的下一步。
4. 项目成果预览。

不以任务完成比例伪装项目完成度。镜头仍需用户审阅时显示“待选定”，不能因为生成结束就写“完成”。

镜头卡：编号、标题、选定图/视频预览、阶段、一个主操作。

| 镜头阶段 | 主操作 |
|---|---|
| 尚无图片 | 制作参考图 |
| 已有图片候选 | 选择参考图 |
| 已选图，无视频 | 制作视频 |
| 正在生成 | 查看进度 |
| 视频候选就绪 | 审阅视频 |
| 已采用视频 | 预览成果 |
| 生成阻塞 | 处理问题 |

编辑、重排、移除进入详情/更多；重排模式可拖动，并提供可访问的上移下移。计划是系统协调流程的对象，不要求普通用户手工“新建选图计划”。

### 4.4 素材库：先看见，再使用

默认缩略图网格，支持类型筛选和搜索；“未加入项目”作为筛选，不强迫用户理解收件箱机制。导入为次级常用操作，回收站放更多菜单。

详情默认只显示当前查看版本的预览；历史版本用缩略图带或版本选择器切换。常用操作为“用于创作”“加入项目”“导出”；描述/标签通过编辑入口调整；设默认、封面、删除进入更多。

“加入项目”打开可搜索选择器，选择后固定当前版本。不要为每个项目生成一个按钮。使用位置显示“项目 A 使用版本 2”，并可跳转。

版本术语保持具体：素材默认版本、本项目采用、此镜头采用分别标记。“候选”必须有上下文，不能把所有非默认版本都说成未被采用。

### 4.5 助手：对话中的创作控制台

将“Prompt 助手”统一命名为“创作助手”。顶部常显当前项目和工作状态，项目切换进入选择器。项目/镜头/草稿页的“让助手协助”传入明确对象，开启或恢复匹配会话。

聊天时间线支持业务卡片：

| 卡片 | 用户可理解的信息 | 操作 |
|---|---|---|
| 计划摘要 | 要做什么、几张图/几个视频、在哪里等待选择 | 开始、调整 |
| 草稿 | 内容摘要、比例、参考图、所属镜头 | 编辑草稿、生成 |
| 生成进度 | 真实执行状态、已就绪结果 | 查看结果、查看详情 |
| 选择 | 候选缩略图、当前选中项、后续动作 | 采用、采用并继续 |
| 修改建议 | 修改前后差异、影响对象 | 采用、保留原文 |
| 成果 | 图片/视频预览、用途、版本 | 继续修改、导出 |

`draft.createImage` 等命令名放执行详情，不作为主要卡片标题。卡片状态来自持久化回执与任务，不靠模型文字声称完成。

默认协作方式：助手准备草稿和计划，用户在消费或关键选择节点确认。有有效有限授权时，范围内执行无需重复弹窗；授权不足或过期时在当前步骤补充。

授权卡说明具体动作、服务、次数、费用已知/未知及有效范围。“最多 3 次图片请求”不等同于“金额封顶”，费用未知必须说明无金额上限。参数、次数或范围变化超出授权时重新核对，不沿用过时确认。

手动打开 Agent 草稿后编辑同一份对象；返回聊天展示“草稿已更新”，后续工具读取新 revision。已提交内容是冻结快照，修改结果必须创建新草稿。发现并发冲突时显示变化，不能覆盖用户编辑。

当前 Agent 创作工具要求项目范围。个人创作里调用助手时，首期先提供明确的“创建并用于本次创作”或“选择项目”，用户选择后绑定；不要暗建不可见项目。真正无项目的 Agent 协作作为后续范围模型扩展。

### 4.6 视频工作台与任务中心

视频工作台以参考图、动作/运镜描述为主体，常用参数显示时长与清晰度；Seed 收到高级设置。引用图显示来源和版本，能够返回查看，不把 NovelAI 图像标签自动当视频提示词。

任务中心分“进行中 / 待处理 / 历史”。任务行展示缩略图、创作标题、所属项目、可理解的状态；默认隐藏编号、凭据代次、回执等内部字段。

任务详情提供返回来源和查看结果。完成后成果自动回到原工作台和项目，任务中心不成为另一个成果仓库。

## 5. 用户使用路径

### A. 第一次生成图片

打开创作 → 图片 → 输入描述 → 选比例 → 生成 → 缺少账号时连接 NovelAI → 回到原草稿并确认本次生成 → 原位查看进度 → 看图 → 保存到相册或继续修改。

首次连接只要求当前需要的服务，不要求先配置 H3 和 LLM。连接成功不等于授权生成，不自动提交收费请求。取消连接保留草稿。

### B. 从图片继续制作视频

图片结果或素材详情 → 制作视频 → 携带选定图片版本和项目上下文 → 填写动作与运镜 → 必要时连接 H3 → 确认生成 → 原位查看视频 → 采用到镜头或导出。

不经过“返回资产库—找图—找版本—新建草稿—任务列表找任务”的串联。个人图片也能建立视频草稿，不强迫补建项目。

### C. Agent 辅助项目制作

新建项目/打开已有项目 → 让助手协助 → “先做天文台参考图，选好后生成推近镜头” → 助手展示计划及图片草稿 → 确认图片生成 → 选择候选 → 确认/使用有效视频授权 → 生成视频 → 审阅并采用。

图片未选定时后续视频等待；未授权自动选图时 Agent 不代选。需要多张候选时按当前单张请求能力生成多个明确任务，并按请求次数展示授权。

### D. 手动与 Agent 互相接续

助手草稿卡 → 编辑草稿 → 手动改描述/比例 → 返回助手 → “按当前草稿继续” → 查看更新摘要 → 在授权范围内生成。反向路径：手动草稿 → 让助手调整 → 查看修改建议 → 应用到同一草稿。

切换项目时显示新范围；旧项目仍在执行的任务留在旧项目，不迁移归属，也不把旧图静默带入新会话。

### E. 离开后回来

后台执行中离开 → 再次打开 → 创作首页“继续创作”或项目待办定位 → 已完成则看结果，需选择则继续选择，异常则恢复处理。

恢复的是对象、输入、选择和执行状态，而非仅打开一段聊天历史。关闭助手不取消已提交生成。

## 6. 状态与异常文案

| 情况 | 呈现 | 主操作 |
|---|---|---|
| 未配置服务 | “连接 NovelAI 后即可生成，当前草稿已保留” | 连接账号 |
| 正常保存 | 顶部小状态“保存中 / 已保存” | 无需额外点击 |
| 保存失败 | “修改尚未保存”，保留编辑内容 | 重试保存 |
| 生成中 | “正在生成，可离开此页” | 查看进度 |
| 远端完成，本地文件未就绪 | “生成完成，正在取回文件” | 查看传输状态 |
| 等待用户选图 | 直接展示候选和下一步摘要 | 选定并继续 |
| 原件缺失 | 预览可保留，明确“原文件待恢复” | 恢复文件 |
| 请求结果未知 | “暂时无法确认是否生成成功” | 核查原任务 |
| 下载失败 | “生成已完成，文件下载失败” | 重试下载 |
| 明确生成失败 | 原因与可修复项 | 修改后重试 |
| 授权过期 | 当前步骤和剩余工作摘要 | 确认继续 |
| 版本冲突 | 展示较新的内容和自己的修改 | 查看差异 |

“停止助手”仅停止后续决策和工具调用；已提交任务能否取消按服务能力呈现。未知结果不使用泛化“重试”按钮，以免重复消费。新一轮生成、重新下载、查询进度必须是不同动作。

## 7. UI 规则与适配

- 保留现有绿色强调色和基本主题；先重建层级，再做色彩与视觉精修。主色用于主行动与选中状态，管理动作使用中性样式。
- 同一操作区只有一个高强调主按钮；页面常用次操作不超过两个，其余放明确的更多入口。
- 8dp 间距基线；页面边距 16dp；正文建议 16sp，辅助文字 13–14sp，尊重系统字体缩放；触控区域至少 48dp。
- 媒体优先展示真实缩略图和比例，预览使用 contain，列表裁切不改变最终成果。不要用一串标题替代选图。
- 编辑器底部保留生成操作和费用摘要；键盘弹起时收起主导航，预览压缩或移出编辑焦点，保证输入及主操作不被遮挡。
- 窄屏一次处理一种任务：复杂角色、参数、选材进入全屏子页。简单菜单可用底部弹层，避免多层弹层相互覆盖。
- 大屏可把媒体预览与设置分栏，但保留相同的信息架构与动作含义。
- 错误靠近发生位置；全局提示不替代可操作的错误说明。颜色同时配文字或图标，不单靠红绿区分状态。
- TalkBack 标签描述动作对象，例如“采用图片 2 作为镜头 03 参考”，选中态和任务变化需可感知。

## 8. 能力边界与实施顺序

本轮源码中的 `novelAiProtocol.ts` 请求使用 `n_samples: 1`，图片编辑器尚未提供参考图输入。因此数量选择、多图批量、图生图、Vibe、精确参考不能只画进界面便声称可用。当前落地以单张文生图、角色与已支持参数为准；参考能力必须先完成适配、验证和能力声明。模型切换不得静默丢弃配置。

旧设计文档中仍有“尚未实现”的历史状态，不能用来判断当前落地程度；实现拆分以当前源码和测试为准。

| 阶段 | 改造内容 | 主要落点 | 完成条件 |
|---|---|---|---|
| P0 主路径 | 创作入口统一；账号面板收敛；图片工作台；结果就地审阅；任务精确定位 | create、ImageDraftScreen、VideoDraftScreen、CreativeAccountPanel、任务路由 | 已连接用户完成“出图→修改→视频草稿”不用寻找全局列表 |
| P1 统一协作 | 助手上下文常显；业务卡片；按计划授权；手动编辑接续；项目待办 | AgentScreen、AgentCreativePanel、ProjectPlans、ProjectActivityPanel | 同一项目/草稿可往返，选图与授权在需要时出现 |
| P2 组织与复用 | 拆分项目与资产路由；镜头状态驱动；缩略图选材；版本比较与项目选择器 | CreativeWorkspace、ProjectShots、VersionComparison、creative-drafts | 资产/项目数量增长不增加每个版本的操作按钮数量 |
| P3 增量能力 | 经验证的参考模式、批量候选、无项目 Agent 协作 | 协议、能力声明、范围模型及 UI | 能力真实可用后开放对应入口 |

实施依赖：P0 优先补精确任务/结果路由和上下文传递，P1 再在业务卡片复用；P2 视觉选材组件可提前支撑 P1。复用现有命令服务和任务状态，不建立第二套 UI 自有执行状态机。已存在的深链接保留或重定向，用户草稿和历史任务不能因导航改造不可达。

## 9. 验收方法

以下是拟定目标，不是已测得的结果。先录制现版基线，再用相同任务比较。

1. 已连接用户从创作首页到第一张图片提交只需“输入→生成→必要确认”，不要求新建项目、进入设置或打开高级参数。
2. 用户在图片结果页能直接继续修改、建立视频草稿；不需全局搜索刚生成的版本。
3. 新用户能在 10 秒内指出当前项目、当前阶段和下一步；找不到视为导航/层级问题。
4. 给出三张候选时，可通过缩略图比较并采用；任务完成不自动替代已采用版本。
5. 助手草稿手动修改后继续执行使用新内容；并发改动不丢失；超出授权范围不能提交。
6. 应用重启、离开聊天、切换项目之后仍能定位原任务；不会重新发起未知结果请求。
7. 用 320/360/412dp、1.0/1.5/2.0 字体缩放、键盘展开验证：主操作可达、文字不截断、选图不依赖横向溢出。
8. 用 0/1/20 个项目和 1/20 个版本验证：页面保持清晰，素材动作数量不随项目数倍增。
9. 分别测试缺少 NovelAI、缺少 H3、无 LLM、余额/费用未知、原件缺失和下载失败；只请求当前任务需要的配置。
10. 先进行 3–5 位目标用户的形成性试用，记录任务完成率、误操作、往返页面次数和求助点；不将小样本当作统计证明。

建议首先以“快速出图→选择图片→制作视频”和“助手提出计划→用户选图→继续同一计划”制作可点击原型并试用。这两条路径通过后，再把组件与导航规范推广到全站。
