# 工作区交互收敛评估

日期：2026-10-24。评估基线：`a5fa8e04`。本文保留改版前的评估与阶段建议。用户随后确认两个主工作台，最新决策、已实现范围及验收记录见 [双工作台与交互收敛](2026-10-24-dual-workbench-design.md)。以下效率目标仍需真实用户测试验证。

## 判断

两轮增加功能后，页面的职责边界再次松动。Enhance、独立超分和元数据各自有价值，但目前主要通过追加按钮接入。结果页同时承载成果审阅、下一次创作、文件检查、版本选择、项目采用和跨工作区跳转，用户需要不断重新判断哪个按钮是下一步。

先前将 Enhance 直接提升为独立实心主按钮，没有同步重排已有的继续修改、保存与采用动作，是本轮发散的直接原因之一。继续调间距、颜色或把每个区块折叠，只能暂时降低视觉密度，不能解决操作竞争。

原建议保留四个一级入口；后续按用户明确方向改为“手工工作台 / Agent 工作台”，项目和素材改为共享资源视图。增强仍归属于图片处理，不新增一级工作区。

## 统一的信息层级

1. 对象层：正在看哪张图、哪个镜头、哪份草稿。标题和预览始终稳定。
2. 当前任务层：此刻在创作、审阅、增强还是选材。每个状态只突出一个主操作。
3. 调整层：完成当前任务所需的参数。点击相应工具后才进入。
4. 检查与管理层：生成信息、版本历史、使用位置、名称标签、文件恢复、归档。各有明确入口，不能全部追加到画布下。

一级导航切换工作区；二级页面操作对象；短面板调整当前工具。弹层用于短选择与少量设置，长提示词、角色编辑、元数据和比较使用有返回关系的子页。窄屏子页和宽屏侧栏可共享内容组件；不要机械地把所有内容都变成弹窗。

## 各工作区的默认页面

| 工作区/页面 | 默认看到什么 | 常用直达 | 按需进入 |
|---|---|---|---|
| 创作首页 | 新建图片/视频、最近创作缩略图与真实状态 | 新建、继续已有创作 | 全部记录；旧工作流归入工具/高级入口 |
| 图片编辑 | 画布/底图、描述输入、模型与比例摘要、固定生成栏 | 编辑描述、模型/比例、生成 | 负面描述、角色、采样器与种子等专业参数 |
| 图片结果 | 当前图片、选中版本、紧凑成果工具栏 | 调整画面、增强/放大、保存或用于镜头 | 图生图/局部重绘、制作视频、完整历史、项目关联 |
| 视频编辑 | 参考画面、动作与运镜、时长和画质摘要 | 换参考图、改描述、生成 | 多图排序、Seed 与专业选项 |
| 项目 | 项目列表；项目内默认分镜与需要处理的项 | 继续当前镜头、审阅候选 | 简报编辑、素材管理、活动与归档 |
| 素材 | 搜索、紧凑类型筛选、媒体网格 | 打开预览、导入、选择素材 | 批量操作、回收站、复杂筛选 |
| 素材详情 | 与成果页一致的媒体预览、版本摘要 | 用于创作、保存、信息 | 加入项目、默认版本、对比、名称标签与删除 |
| 助手 | 会话、紧凑项目范围、当前待决定的卡片 | 发送、审阅当前建议、打开对应草稿 | 历史工具回执、授权管理、完整计划 |
| 任务 | 进行中和需要处理的任务 | 返回原创作、处理明确异常 | 技术日志、编号、监控配置、归档历史 |
| 设置 | 账号、助手、存储、播放与高级分类摘要 | 进入一项设置 | 具体表单；不在首页显示全部输入框 |

项目默认分镜是本轮建议，替代当前默认概览的额外中转；保留概览作为项目摘要入口。没有镜头的空项目显示“添加第一个镜头”，不展示空的进度板。

首页新建直接进入工作台并聚焦描述，已有输入深链接原样转交；不再要求常规路径先在首页写一次再进入编辑。现有首页未完成输入迁移时保留，不能因为改版丢失。

## 图片工作台的状态和动作

| 当前状态 | 主体 | 唯一突出主操作 | 其余内容 |
|---|---|---|---|
| 新建/编辑 | 描述与画布/底图 | 生成图片 | 常用参数摘要；高级编辑按需打开 |
| 已提交、等待或生成中 | 当前提交摘要与真实进度 | 正常等待时不需要主按钮；异常时才显示处理入口 | 允许离开；历史结果明确标注，不冒充本次成果 |
| 成果审阅，个人创作 | 当前成果与紧凑候选 | 保存到相册 | 调整画面、增强/放大保持可见；信息放标题栏 |
| 成果审阅，项目镜头 | 当前成果与采用状态 | 用于此镜头；已采用后显示状态 | 调整画面、增强/放大保持可见；导出在菜单中 |
| 增强/放大 | 固定来源图与专用参数 | 增强图片或放大图片 | 不显示角色、蒙版、素材关联和其他成果工具 |
| 失败/结果不明 | 可理解的原因和受影响步骤 | 检查原任务/恢复原件等具体动作 | 不能把重试和重新付费生成混为一谈 |

顶部是返回、对象标题、信息/更多；中部是媒体和版本；底部是当前状态的操作区。长图不应把核心操作挤到屏幕以下。个人/项目的主动作按明确上下文决定，不按算法猜测用户意图，不随点击历史随机换位置。

版本选择默认显示当前版本与少量候选；较多历史通过“版本历史”进入独立浏览与比较。当前选中版本、素材默认版本、镜头采用版本分别标记。浏览历史只改变选择，不改变采用关系。

### Enhance 与独立超分

成果工具栏只保留一个高可发现的“增强/放大”入口，点击后进入同一图片处理工作模式：

- “细节增强 · Enhance”：倍率、五档变化幅度；高级展开 Strength/Noise。保留模型/Effort 摘要与必要修改入口。
- “清晰放大 · 2×”：显示输出尺寸，说明以尽量保持原画面为目标；不显示不适用的 Strength/Noise，也不承诺像素内容绝对不变。

两个操作使用各自原有 API，不混淆能力和付费行为。来源没有完整生成参数时说明 Enhance 不可用的具体原因；独立超分继续可用。不为不可用的模式展示一墙灰色参数。

新版 UI 不再显示普通图生图内旧的“最大画质增强”开关；旧草稿仍可读取，并明确映射为 Max 增强状态，不能直接清除旧输入。改变处理模式时各自保存输入，不把一个模式的强度或尺寸带入另一个模式。

选择工具仅进入编辑，不发起生成。实际发起操作继续经过已有费用确认与持久化队列。关闭处理界面保留草稿；取消费用确认不提交；再次进入继续同一草稿。处理成功选中新的成果版本，可进入前后对比；不自动修改项目或镜头已采用版本。

### 元数据与参数

结果和素材详情共享“信息”入口，正常情况一击到达，不藏到多层“更多”里。信息页默认只显示尺寸、格式、文件大小、模型与生成摘要；完整提示词、角色、Seed 等分组展开，原始 JSON/哈希进入“技术信息”。

信息页是只读检查，不与名称标签编辑混合；从信息恢复参数时先预览目标草稿，不能默默覆盖正在编辑的内容。继续保持内嵌元数据与 App 生成记录的来源说明，缺失字段不猜测。信息读取失败不阻断看图、保存和进入其他操作。

## 页面边界与实现约束

第一步拆分展示职责，再调整样式：

- `CreativeResults` 拆为媒体预览、版本选择、状态条和成果工具栏；操作由页面明确给出，预览组件不再自主枚举所有生成与管理能力。
- 图片、视频、增强与独立超分共享工作台外壳及保存/离开行为，各自拥有任务参数区。共享布局不意味着共享一份巨大条件表单。
- `CreativeWorkspace` 逐步拆为项目列表、项目详情、素材列表和素材详情。搜索、更多、版本选择、项目关联等 UI 状态归属具体页面。
- 使用一份按上下文和可用能力确定的动作清单，声明入口分组、位置、不可用原因和目标对象；同一能力在不同页面入口最终进入同一处理流程。
- 清晰区分草稿编辑状态、任务执行状态、文件归档状态、当前查看版本与界面模式。不得仅凭 `SUBMITTED` 当作生成完成，也不能把关闭面板当成任务取消。
- 返回保留来源页、滚动位置、已选版本和草稿。成果到任务再到成果不反复压入相同路由；深链接有明确后备入口。
- 助手卡片优先关联发起它的消息；先实现消息关联和事实状态，再移除独立汇总。授权后自动续跑需要运行时幂等契约，不可仅改按钮文案。

## 实施顺序

1. **优先收敛图片闭环**：成果工具栏、增强/放大模式、旧增强入口归一、元数据信息页。先解决最近两轮直接增加的复杂度。
2. **统一媒体与工作台体验**：图片/视频/素材详情共用预览与版本行为，统一固定操作区和返回上下文；首页简化为新建与继续。
3. **收敛组织与辅助工作区**：项目以镜头推进；素材管理按需进入；任务区突出异常；设置真正分层。
4. **优化助手协作**：将计划、授权与结果卡与消息对应，解决续执行断点，减少重复导航。

每一步单独交付可复查结果；不把页面拆分、全局路由迁移、授权运行时重写混在一次大改中。

## 验收标准（设计目标，尚未测量）

- 在 360dp 窄屏，结果页的预览和主操作不依赖滚动整张长图才能找到；触控目标至少约 44–48dp，支持字体放大。
- 默认状态只有一个高强调主操作；成果常用工具控制在三项左右。导航、信息与更多使用低强调表达。
- 结果→Enhance/独立超分选择、结果→信息均为一次入口点击；不以无限嵌套菜单换取表面干净。
- 元数据、专业参数或项目管理再长，也不增加默认结果页高度。
- 依次覆盖首次出图、再次修改、增强、独立超分、看信息、用于镜头、返回素材七条路径，验证选中图和草稿不丢失。
- 生成失败、响应已保存但导入未完成、原件缺失、额度未知、并发更新、进程重启均有对应状态；改版不改变幂等和恢复策略。
- 新功能接入前明确：属于哪个对象、在哪个任务状态出现、替换或归并哪个入口、无权限/不支持时如何呈现。禁止默认在 `CreativeResults` 末尾追加按钮。

## 参考依据

上述页面划分是针对本项目的设计推导，不是对参考产品界面的照搬。

- [Adobe Photoshop Contextual Task Bar](https://helpx.adobe.com/photoshop/desktop/get-started/learn-the-basics/boost-workflows-with-the-contextual-task-bar.html)：随当前选择提供相关动作，支持将成果操作约束在当前对象与任务上。
- [Material Design Menus](https://m2.material.io/design/components/menus.html)：菜单承载按需出现的动作，窄屏可使用底部操作面板；适合低频工具与管理入口。
- [Apple Human Interface Guidelines — Modality](https://developer.apple.com/design/human-interface-guidelines/modality)：模态交互形成独立工作模式；本项目只为聚焦的短任务采用，长编辑使用明确子页。

与既有设计的关系：保留草稿恢复、版本不可变和按阶段给下一步；以双工作台取代原四入口建议，逐步落实各功能的状态表与页面边界。
