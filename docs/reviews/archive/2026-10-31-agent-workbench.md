## 如何理解闭环

- **已记录修复**：有实现、提交和测试记录；不自动等于独立复核。
- **原路径复核通过**：后续审查实际核对了原问题；结论仅覆盖该报告注明的源码/设备/离线条件。
- **验证待补**：缺新版设备、真实服务、长数据、无障碍或故障矩阵证据；不能把“已修复”改写成“全部验收”。
- **历史提案**：记录当时建议，不自行升级为当前需求；现行提案和任务流程集中在 `docs/design/`。

本次整理没有重跑历史模型请求、探针或产品测试。下表状态来自已存在的实现记录与后续复核，不将归档工作算作新一轮产品验收。各报告中的“当前”、源码行号和优先级均属于当时基线。

## 仍有效的验证边界

现行页面职责、技能选用/管理分工、补配置回流、镜头制作与采用、交付展示见设计谱系，不复制成另一套当前待办。真实模型/付费生成授权链、ARM/OEM 恢复、长会话性能、TalkBack/大字体等，按已有验证记录的实际覆盖继续判断；没有证据时保持待验，不以历史通过项替代。

历史探针部分刻意断言错误仍存在。修复后原样复跑可能失败，这是旧基线证据的性质，不能据此宣布现版本回归；正式正确性回归位于产品测试目录。本次保留独立复现源码和最终结果，省略重复运行及采集脚本。

[完整存放与哈希清单](2026-10-31-agent-workbench.json)记录原路径、原始字节数、原始 SHA-256、是否入库及整理后的文件哈希。`originalSha256` 对应 ZIP 原始字节，`retainedSha256` 对应 Git 文本规范化后的 blob，避免不同系统换行符造成误判。ZIP 保存整理前的报告和证据，先逐文件校验成功，再移出已知未跟踪的非精选原件。已跟踪的文件全部保留原路径；证据 README 仅增加归档说明和精选清单。原报告除归档状态、链接、失效约束提示及空白格式外，不重写当时的发现。

恢复时先核对 ZIP 的 SHA-256，再按清单提取所需文件到临时目录并逐文件验哈希；不要直接覆盖当前仓库的整理版报告。ZIP 中的机器路径链接属于历史原文，不能重新作为当前文档发布。需要对外共享未入库原件时，单独提供该归档包。
