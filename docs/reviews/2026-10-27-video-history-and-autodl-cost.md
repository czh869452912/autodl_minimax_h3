# 视频生成记录与 AutoDL 费用接入评估

2026-10-27。下文保留评估与交互方案；用户认可后已实施记录布局、动态估价与可选余额查询。公开资料和公开工作流元数据只读核查，没有提交付费任务，也没有读取用户私有令牌。价格证据见同目录 `2026-10-27-autodl-price-evidence.json`。

## 本轮实施

- 记录条改为小型完整封面；全部记录在原区域展开并按状态筛选，宽屏使用侧栏。当前轮次耗时始终可见，工作流显示友好名称。当前播放器不会因别的轮次完成而自动切走；仍支持同轮多输出选择。
- 历史轮次序号按 session 保存到本机存储，删除其他记录后不重排已有序号。隐藏记录区域停止列表查询，已完成且下载就绪的记录停止列表轮询。列表使用 FlatList 有界渲染；本轮未新增数据库级分页。
- 视频记录中的保存与任务入口统一进成果更多菜单，沿用已有复用参数和查看参数操作。
- 生成按钮附近显示公开价格的区间估算，价格缓存最多五分钟；定期刷新失败不继续报价。提交时将有效报价存入本地创作上下文，参数详情显示“提交时预估”，不修改发往服务商的输入或预算授权。
- AutoDL 账号设置增加可选开发者 Token 配置，验证余额响应后保存到安全存储。与 ComfyUI 凭据独立；要求用户确认同账号，无法自动验证账户归属。更换或断开生成账号会移除余额配置。
- 工作台仅在配置后显示余额摘要，详情区分现金、代金券、累计消费与更新时间。不用账户余额差计算实扣，不据此阻止生成。
- 验证覆盖价格单位／过期／无效数据、独立凭据及更换清理、历史选中保持／隐藏与终态停止读取、提交报价不污染请求、设置和参数详情兼容性。真实开发者 Token 查询仍未实测。
- 验证结果：10 个相关测试文件共 74 项通过、1 项原有跳过；TypeScript 检查通过。x86_64 Android beta 编译并安装成功，模拟器验证了动态估价（5 秒 768p 为 ¥0.20–0.25）及余额配置布局，截图在 `evidence/2026-10-27-video-cost/`。模拟器没有视频历史，真实多轮播放尚未端到端验证。后续已随 beta.16 提交并交付双 ARM 手机测试 APK，见 testing-phone-beta.md。

## 现状与问题

- `VideoGenerationHistory.tsx` 已按创作 session 查询多轮任务，支持记住选中轮次，并按 job ID 对应结果，基础归属可以保留。
- 当前每轮横向卡片宽 156，封面 142×56，封面过扁；每张重复状态与耗时，主预览下方又显示一次相同信息。轮次多时横向查找效率低。
- “查看最新一轮”“查看本轮任务”占据额外行；工作流使用原始 ID 展示。
- 轮次号由 `rounds.length-index` 临时计算，历史被删除或补录后可能改变，不宜作为持久版本标识。
- 默认优先选有 AVAILABLE 结果的轮次。因此顶部新任务正在执行时，主画面可能显示旧轮次；必须清晰区分“正在看什么”和“最新任务进度”。
- 隐藏记录视图后仍每 2.5 秒读取所有草稿、版本和逐条任务；这会造成不必要的数据库查询和整列表刷新。任务同步与记录展示刷新应分离。

## 推荐组织方式

归属保持“项目／镜头 → 一次创作 → 生成尝试 → 输出文件”。一次创作可包含跨工作流尝试；每次提交保留不可变输入快照。一轮可以产生多份输出，不能只保留 `versions[0]`。

工作区内的生成记录用于审阅当前创作；全局任务列表用于跨创作的执行管理。两处引用同一个任务和结果，不复制另一套历史。

窄屏结构：

```text
生成记录                  12 轮 · 2 项进行中
┌─────────────────────────────────────┐
│            当前视频播放器             │
│         播放 / 进度 / 音量 / 全屏       │
└─────────────────────────────────────┘
第 8 轮 · 10 秒 · 768p       已保存  ⋯
排队 24 秒 · 运行 3分18秒       参数

[第12轮 生成中] [第11轮封面] [第10轮封面] …
                              全部 12 轮
```

这是一份信息布局草图，耗时与参数均为示例。

- 主播放器不随任务轮询重建。只挂载当前输出的播放器，相邻记录只缓存封面；切换先停止旧视频，防止多解码器争抢资源及后台声音。
- 播放控件交给播放器，不在外层重复播放、全屏按钮。保存、复用配置、查看任务、采用到镜头收进单个更多菜单；保存成功使用状态标记，不留下浮动大按钮。
- 当前轮次的排队／运行时间始终一行可见，任务执行时动态更新。素材下载单独显示，不能把下载耗时算进生成运行时间。
- 版本条封面用统一容器，默认 16:9，竖视频完整适配并留底色。仅显示轮次、视频时长、小状态标记；不再给每张封面堆两行技术摘要。
- 选择旧轮次之后，新的任务完成只更新版本条与进度提示，不抢走播放源。首次进入默认选择最近可播放结果，并明确标出最新进行中任务。
- 版本切换不覆盖编辑草稿。“复用本轮配置”是显式动作；失败和状态未知的轮次也保留，核查状态不能隐式重新生成。
- 若一轮有多个视频，当前轮次下增加紧凑的输出选择；这些输出共享提交参数和任务耗时，不伪装成多轮提交。
- “全部记录”在同一结果区域展开为可滚动的紧凑列表，不再开抽屉套详情。固定行包含封面、轮次／时间、状态、排队／运行、更多；点击行切换当前预览。长列表虚拟化、分页加载，支持全部／完成／进行中／失败筛选。搜索可后续按实际记录规模增加。
- 宽屏将记录列表放在播放器侧边，沿用同一选中状态；屏幕宽度变化不重新选图、不重置播放进度。
- 历史新增／状态变化只更新对应行；避免整列表 LayoutAnimation。支持减少动态效果，切换使用短淡入或加载占位，不用无限转圈掩盖加载失败。

数据调整：为提交尝试记录稳定序号与创建时间；复用已有 session/job/assetVersion 关联。终态记录不持续轮询，隐藏视图停止展示层查询，后台任务同步继续运行；恢复可见时增量刷新。采用已有封面缓存与有界提取队列。

## AutoDL：可以接哪些费用信息

### 生成前估价：具备实现条件

公开工作流元数据：
`GET https://www.autodl.art/api/v1/comfyui/workflows/minimax_h3_image_audio_to_video_v2_15s`

本次返回 `price_type=minimax_h3`，价格在 `billing_config.minimax_h3`。顶层 `price=0`、`billing_interval_seconds=0` 不能当作免费。

官网前端 `detail.55eb8f36.js` 展示元／秒和高峰 08:00–24:00、空闲 00:00–08:00；金额格式函数 `utils.6745955e.js` 将原始值除以 1000。

| 清晰度 | 高峰单价 | 空闲单价 | 10 秒示例区间 |
| --- | --- | --- | --- |
| 480p | ¥0.040／秒 | ¥0.030／秒 | ¥0.30–0.40 |
| 768p | ¥0.050／秒 | ¥0.040／秒 | ¥0.40–0.50 |

以上是 2026-10-27 公开价，不应硬编码为永久价格。估价按所选视频时长计算，不按 GPU 运行时间或排队时长计算。时区及按提交、开始还是结算时刻选时段，尚未获得权威确认；初期显示区间更稳妥，不能用手机本地时间承诺低价。

接入需按工作流/price_type 解析，输入变化重新估价，保留价格来源与查询时间。未知价格类型、过期／请求失败显示“暂无法估价”，不显示 0。估价写入提交快照，供历史查看；不把它当实际扣款或硬预算上限。

### 余额：公开接口存在，需要独立开发者凭据验证

[官方通用 API](https://www.autodl.com/docs/common_api/)：
`POST https://api.autodl.com/api/v1/dev/wallet/balance`，使用 AutoDL 开发者 Token。
返回 `assets`（余额）、`accumulate`（累计消费）、`voucher_balance`（代金券余额），均除以 1000 得到元。

官网公开前端说明“AutoDL.Art和AutoDL同一账号共享钱包和代金券余额”。但 [ComfyUI API](https://www.autodl.art/docs/comfyui_api/) 要求 ComfyUI 分组令牌，不能默认与开发者 Token 可互换。

推荐在现有 AutoDL 账户设置中增加可选的“余额查询凭据”，保留现有生成凭据；验证对应账号后绑定，切换账户时清除旧余额缓存。不要索取网页登录 Cookie。凭据权限未做实测，文档中的余额接口不等于现有生成 Token 已能调用。

官网网页另有 `/api/v1/adl_server/wallet/balance` 和 `/api/v1/mllm/user/info`，来自公开 JS，但不是已确认可供 ComfyUI Token 使用的公开契约，不建议作为第一版依赖。

### 单任务实际扣款：本次未确认可接入

公开 ComfyUI 结果示例提供状态、时间与结果 URL，没有明确的任务实扣字段。不能把生成前后余额差当成单任务费用：并发任务、其他消费、充值及代金券都会影响它。历史优先显示“提交时预估”；只有收到可关联该 task ID 的账单信息，才展示“实际扣费”。

余额和代金券分开展示，不直接相加作为本次可用额度，代金券适用条件尚需确认。

## 费用的界面位置

- 视频生成按钮旁的小字显示“预估 ¥0.40–0.50”，点击查看分辨率、时长、价格来源和时段说明。
- 账户余额放在现有顶部账户入口的紧凑摘要中，展开查看现金／代金券／更新时间，不再增加占高的常驻横条。
- 未配置余额凭据不阻碍原有生成；读取失败标明未更新，不能伪装成余额为 0。余额不足只能作提示，考虑折扣和代金券适用性后再决定是否有依据禁用。
- 记录详情分别列提交时预估和实际费用；无实扣信息时不显示假的“已消费”。

建议实施顺序：先整理记录布局与刷新机制，再接公开元数据估价，最后验证独立开发者 Token 的余额查询及账户对应关系。验收覆盖连续多轮、并发完成、回看旧轮次不跳转、多输出、失败／缺文件、百轮滚动、价格过期、时段边界与账户切换。
