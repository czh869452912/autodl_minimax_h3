# C/D Durable Executor and Product Domain Implementation Plan (Superseded)

> This original combined plan has been split into three independently gated plans: `2026-09-01-b1-closure.md`, `2026-09-01-c-core.md`, and `2026-09-01-d-core.md`. Use those files for execution; this file remains as the detailed historical review and broader roadmap.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 A/B 结果纠偏和 Android 门禁后，先建立不会重复计费且可跨进程恢复的本地 Durable Executor（C），再建立可追溯、版本不可变的 Project/Prompt/Asset/Batch/Delivery 产品域（D）。

**Architecture:** SQLite snapshot + append-only event log 是唯一权威状态；DurableExecutor 以 operation lease、稳定幂等键、revision/CAS 和持久化 retry 驱动 provider adapter。D 在 C 的 job/artifact 投影上增加 immutable revisions 与 CAS 引用，不改写历史 job、不依赖业务服务器。

**Tech Stack:** React Native 0.86.3, Expo SDK 57, TypeScript 6, Jest 29, expo-sqlite, Expo background task/Headless JS, Gradle 8.13。

**Spec:** `docs/superpowers/handoffs/2026-09-01-c-d-stages-handoff.md`；架构依据 `docs/superpowers/specs/2026-09-01-local-first-workflow-architecture-design.md`。

## Global Constraints

- 本地 SQLite、任务队列、Workflow Registry、项目/资产索引和应用私有文件是权威状态；不引入业务后端、云端数据库、webhook receiver 或远程 orchestrator。
- 外部网络只允许用户配置的 LLM/生成 API，以及固定、用户批准的 Git 仓库；Git 内容只能是签名声明式 JSON 数据，不能下载或执行代码。
- Provider adapter 必须随审核过的 app 版本发布；不从 Git 下载动态 adapter/plugin。
- `UNKNOWN` 只能使用原始 provider handle 对账，不能默认重新 submit。
- PromptRevision、AssetVersion、WorkflowPackage、WorkflowJob 语义不可变；编辑只能产生新版本。
- 后续 schema 变化必须提升明确 `APP_SCHEMA_VERSION`，事务内可重复执行并在迁移前保留备份；普通升级不得 DROP legacy 表。
- 使用隔离 worktree；主工作区 `local.properties` 保持未修改、未提交；行为变更遵守 RED → GREEN → REFACTOR。

必须纳入 C0/C1 的真实差距：

1. **[高] package 边界绕过：** `mobile/src/workflows/registry/service.ts:30-32` 对非 `workflow.autodl/v1` payload 直接接受 legacy definition，远程/Git 内容不必经过 `parseWorkflowPackage`。
2. **[高] provenance/hash 错位：** `service.ts:113-120` 将 package 转 legacy definition 后再 hash 并只存 definition JSON，丢失 envelope/signature/capabilities/limits，无法按 package attestation 校验。
3. **[高] `fetchAndActivate` 名不副实：** `service.ts:90-108` 校验并 upsert 远程版本后没有调用 `setActive`；成功同步不会更新 active pointer，CreateForm 仍可能继续使用旧版本。
4. **[高] 下载先写后验：** `mobile/src/tasks/download.ts:29-32` 完整 `downloadAsync` 后才检查大小；没有流式上限、逐跳 redirect 校验，超大响应可耗尽私有磁盘。
5. **[中] host allowlist 未接线：** `mobile/src/tasks/media.ts:64-69` 调用下载时不传 `allowedHosts`；实际路径只检查 HTTPS，不检查 adapter 允许域名，缺失 MIME 也被容忍。
6. **[中] Runtime provenance 不一致：** `mobile/src/workflows/runtime/runtime.ts:38-50` 未校验 draft 的 workflow id/version/content hash 与传入 definition 一致，可持久化矛盾 job snapshot。
7. **[中] B 验收未闭合：** `mobile/src/workflows/registry/builtin.ts:1-10` 仍 bootstrap legacy H3；`CreateForm.tsx:64,150-166` 固定 `records[0]`、截断 UI section、硬编码 AutoDL/50MB；没有第二 builtin adapter/request fixture。
8. **[中] schema 仍非版本化迁移：** `mobile/src/storage/database.ts` 与 registry/job repositories 直接建表/ALTER，没有 transactional migration、backup、read-only recovery、revision/CAS。
