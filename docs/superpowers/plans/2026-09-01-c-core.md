# C-Core Durable Local Executor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 submit、status sync 和 artifact download 改造成可跨进程恢复的 SQLite operations，并确保任何不确定的 provider 提交都不会被自动重复执行。

**Architecture:** schema v6 一次性提供 operation queue、append-only job events、revision/CAS job snapshots 和 Artifact CAS metadata。所有入口通过同一个有界 executor tick 工作；提交进入 `SUBMITTING` 后若失去确定结果只能进入 `UNKNOWN`，有 opaque handle 时只轮询原任务，无 handle 时保持 `BLOCKED` 等待显式人工决策。

**Tech Stack:** TypeScript 6.0、Jest 29、`node:sqlite`、Expo SQLite 57、Expo FileSystem 57、Expo BackgroundTask/TaskManager、React Native 0.86。

**Spec:** `docs/superpowers/specs/2026-09-03-c-core-durable-executor-design.md`

---

## Execution Rules

- 从最新 `dev` 创建隔离 worktree；不要在发布基线或用户主工作区直接实施。
- 严格按 Task 1→6 执行。前一 Task 的 focused tests、typecheck 和提交未完成前，不开始后一 Task。
- 每项使用 RED → GREEN → REFACTOR；不要用 `--forceExit` 掩盖 Jest open handle。
- SQLite、应用私有文件和 operation queue 是权威状态。不要引入后端、云队列、webhook receiver 或动态代码。
- 所有 migration 都必须逐版本、事务化、可重复；普通升级不得 DROP legacy tables。
- `UNKNOWN` 不得进入 submit retry。没有 handle 的 UNKNOWN 只能由显式用户确认创建一个全新的 job/operation。
- `local.properties`、`mobile/.expo/`、签名文件、token 和真实 provider payload 不得提交。

- [ ] **Step 4: Implement v4→v5, v5→v6, and the runner**

`v5Registry.ts` executes the existing v5 registry/recovery DDL. `v6DurableExecutor.ts` executes `V6_SCHEMA_STATEMENTS` and adds missing columns using `PRAGMA table_info` guards:

```typescript
const JOB_COLUMNS: ReadonlyArray<readonly [string, string]> = [
  ['revision', 'INTEGER NOT NULL DEFAULT 0'],
  ['provider_handle_json', 'TEXT'],
  ['last_error_json', 'TEXT'],
  ['next_sync_at', 'INTEGER'],
];

export const v6DurableExecutor: MigrationStep = {
  fromVersion: 5,
  toVersion: 6,
  name: 'v6-durable-executor',
  apply({ db, exec, hasColumn }) {
    for (const statement of V6_SCHEMA_STATEMENTS) exec(statement);
    for (const [column, declaration] of JOB_COLUMNS) {
      if (!hasColumn('workflow_jobs', column)) {
        exec(`ALTER TABLE workflow_jobs ADD COLUMN ${column} ${declaration}`);
      }
    }
    db.runSync('UPDATE workflow_jobs SET provider_handle_json = remote_json WHERE provider_handle_json IS NULL AND remote_json IS NOT NULL');
    db.runSync('UPDATE workflow_jobs SET last_error_json = error_json WHERE last_error_json IS NULL AND error_json IS NOT NULL');
  },
};
```

The runner first checks for an existing recovery marker and rethrows its stable `AppMigrationError` so a failed fresh v0 remains readonly after the next cold start. It directly creates `CURRENT_SCHEMA_STATEMENTS` only for a truly empty v0, returns `legacy` without mutation for app-owned v0 and schema v1–v3, and returns `future` only for versions above 6. It backs up before opening one transaction for the complete v4/v5→v6 chain and writes `PRAGMA user_version = 6` only after all steps finish. Backup failure writes `BACKUP_<from>_TO_6_FAILED` recovery, throws `AppMigrationError` and never opens the migration transaction.

Implement `createPreMigrationBackup` with a destination opened in Expo SQLite’s application-private directory:

```typescript
export type BackupDeps = {
  now(): number;
  open(name: string): SQLiteDatabase;
  backup(options: { sourceDatabase: SQLiteDatabase; destDatabase: SQLiteDatabase }): void;
};

export function createPreMigrationBackup(
  source: SQLiteDatabase,
  fromVersion: number,
  toVersion: number,
  deps: BackupDeps = expoBackupDeps,
): string {
  const name = `autodl-h3-v${fromVersion}-to-v${toVersion}-${deps.now()}.backup.db`;
  const destination = deps.open(name);
  try {
    deps.backup({ sourceDatabase: source, destDatabase: destination });
    return name;
  } finally {
    destination.closeSync();
  }
}
```

UPDATE workflow_operations
SET state = 'CLAIMED',
    lease_owner = ?,
    lease_expires_at = ?,
    attempt = attempt + 1,
    updated_at = ?
WHERE id = ?
  AND state = 'PENDING'
  AND next_retry_at <= ?

Select and conditionally claim in one transaction, returning only `changes === 1` rows. export async function runExecutorTick(options: TickOptions): Promise<TickSummary> {
  const maxOperations = Math.max(1, Math.min(32, options.maxOperations ?? 8));
