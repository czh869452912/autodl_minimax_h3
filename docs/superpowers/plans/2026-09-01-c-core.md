# C-Core Durable Local Executor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 submit、status sync 和 artifact download 从同步函数升级为可跨进程恢复、不会因不确定结果重复计费的数据库驱动 operations。

**Architecture:** SQLite 保存 operation snapshot、append-only job events 和带 revision 的 job snapshot。Executor 以稳定幂等键和 lease claim 工作；提交超时进入 `UNKNOWN`，只用原始 opaque provider handle 对账，绝不默认重新 submit。

**Tech Stack:** TypeScript 6, Jest 29, expo-sqlite, Expo background task/Headless JS, React Native 0.86.3。

**Spec:** `docs/superpowers/handoffs/2026-09-01-c-d-stages-handoff.md`。

## Global Constraints

- 本地 SQLite、operation queue 和应用私有文件是权威状态；不引入服务端编排。
- 后续 schema 只做 transactional, repeatable migration；保留 legacy tables，不清空用户数据。
- 每个 operation 有稳定 idempotency key、attempt、nextRetryAt、lease owner/expiry。
- `UNKNOWN` 只允许 status reconciliation；retry policy 不得重新创建 provider 任务。
- queue 每轮有界并发；UI 只读取 snapshot/projection，不扫描 event 全表。

## Explicitly deferred from C-Core

Full Android foreground-service integration, MediaStore export/delete delivery, richer MIME sniffing, native ComfyUI adapter semantics, cost policy, Batch/Variant UI and CAS cleanup tuning remain C-Extended or D-Core work. They must not weaken C-Core's submit idempotency, UNKNOWN, lease or restart guarantees.
