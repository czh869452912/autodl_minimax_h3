# D-Core Local Product Domain Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 C-Core 稳定 job/artifact 投影之上，建立离线可用且版本不可变的 Project、PromptRevision、Asset、AssetVersion 和显式关系模型。

**Architecture:** 新域表通过 v6 transactional migration 增加，旧 `tasks`/media 表保留为兼容读取投影。Project、PromptRevision、AssetVersion 使用内容 hash 和父版本形成不可变历史；workflow job 只通过 project links 关联，不被回写。

**Tech Stack:** TypeScript 6, Jest 29, expo-sqlite, React Native 0.86.3。

**Spec:** `docs/superpowers/handoffs/2026-09-01-c-d-stages-handoff.md`。

## Global Constraints

- 离线创建、编辑和查看历史必须可用；网络只用于 provider submit/status 或用户主动同步。
- PromptRevision、AssetVersion、WorkflowPackage、WorkflowJob 不可变；编辑只创建新版本。
- 删除使用 archive/引用检查；CAS 只有无引用且超过保留窗口才 GC。
- 项目 UI 读取 repository/projection，不拼接多个 legacy task 表，不扫描全部 events。
- 导出/导入、Batch/Variant 并发和协作同步不属于 D-Core。

## Explicitly deferred from D-Core

GenerationBatch/GenerationVariant, batch concurrency/cost policy, project archive export/import, backup/sync/collaboration, removal migration and complex workflow UI remain later slices. D-Core is complete only when the immutable offline model and job provenance are reliable.
