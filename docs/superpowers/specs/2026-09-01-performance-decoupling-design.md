# App 全链路性能解耦设计

## 目标

解决长时间运行和历史数据增长后出现的全局交互卡顿、任务刷新阻塞、重复提交、后台重复轮询和设备发热问题，并建立可持续的性能边界。业务行为保持不变：生成任务仍可提交、任务状态仍会自动更新、媒体仍可下载/导出、Prompt 助手仍可流式回复。

## 范围与约束

- 覆盖 React Native/Expo 前端、TypeScript 本地同步层、SQLite Repository、Android 持续监控服务和远端 Provider 适配层。
- 不修改 AutoDL 或 LLM 服务端协议，不引入需要额外部署的服务。
- 保留现有本地数据；数据库迁移必须可回滚或安全降级。
- UI 线程不得等待大文件下载、媒体导出、全历史反序列化或大批量同步写入。
- 同一任务、同一会话、同一调度周期只能有一个有效执行者。

## 设计

### 1. 统一数据库边界

新增数据库单例模块，应用生命周期内只打开一个 `autodl-h3.db` 实例，并集中执行 schema/index 初始化。Repository 对外保留现有接口，内部优先使用异步 SQLite API；同步 API 仅保留在启动时极小的迁移检查中。

增加按 ID 查询和增量查询接口：`tasks.get(id)`、按更新时间的任务增量、会话元数据分页。所有页面禁止为查找单条记录读取全表。

### 2. 任务状态同步与媒体交付解耦

将当前协调器拆为两个阶段：

1. `StatusSyncCoordinator`：只读取活动任务/修复候选，按并发上限调用 Provider，做差异写入，然后立即返回状态结果。
2. `MediaDeliveryQueue`：独立消费下载、封面提取、相册导出任务；使用任务级锁、有限队列和小批量预算，不阻塞状态刷新。

状态同步完成后通过本地事件/版本号通知任务页刷新；媒体进度单独更新对应任务，不触发全量同步。

### 3. 差异写入、重试退避和幂等

Provider 状态结果先与本地 Job/Task/artifact 指纹比较。无变化时不写库；artifact 使用按 ID 的 upsert/delete 差异更新，不再每轮删除后重插。

任务增加同步重试元数据（失败次数、下一次重试时间、最后错误）。网络错误采用指数退避并设置上限；终态任务不再进入 Provider 轮询。提交、状态同步、媒体交付都使用稳定幂等键，重复触发只复用已有执行结果。

### 4. 前台与后台调度中心

前台任务页、Expo BackgroundTask、Android Headless Service 统一调用调度中心。调度中心使用 SQLite 租约/运行标记，而非仅依赖单个 JS runtime 的内存锁；同一时间只允许一个状态同步批次和一个媒体批次。

Android 持续监控保存并传递选中的任务 ID；没有活动任务时自动停止服务。下一次 tick 在上一次 Headless 执行完成后再安排，避免固定间隔造成重叠。应用前台可见时降低或跳过重复后台轮询。

### 5. Prompt 助手增量更新

运行时事件继续即时更新 UI 内存状态，但持久化采用“最新快照合并”：同一会话只保留一个待保存快照，默认 300ms 防抖；流结束、会话切换、退后台执行强制 flush。消息和状态事件合并成一次保存。

时间线只根据消息版本或最后一条消息变化重算；历史页使用分页/虚拟列表，搜索只查询元数据和必要摘要，不扫描所有会话的完整消息正文。技能包在进程内缓存规范化结果；流式网络 flush 合并到单个待处理任务/动画帧。

### 6. 任务列表和媒体页面渲染

任务计时拆成活动行组件，只刷新 QUEUED/RUNNING/UNKNOWN 行；历史成功行不因每秒时钟更新而重渲染。任务列表继续分页，详情页按 ID 查询。

## 数据流

```text
生成/后台触发
      |
      v
Scheduler lease ----> StatusSyncCoordinator ----> Provider
      |                         |
      |                         +--> diff write Job/Task/Artifact
      |                         +--> status event/version
      |
      +------------------------> MediaDeliveryQueue --> download/export

Prompt stream --> in-memory snapshot --> coalesced persistence --> SQLite
```

## 错误处理

- 状态同步失败只记录错误和退避时间，不阻塞页面读取已有任务。
- 媒体失败保留可重试状态，不影响 Provider 状态刷新。
- 租约超时后允许下一次执行接管；进程崩溃不会留下永久锁。
- SQLite 异步操作失败通过统一错误边界上报，并保留最近一次可用内存状态。

## 测试与验收

- 单元测试：快照合并、防抖 flush、任务级互斥、重试退避、artifact 差异写入、调度租约、媒体队列预算。
- 集成测试：空队列进入任务页立即显示新任务；状态刷新不等待下载；前后台触发不会并行同步；同一提交不会重复创建远端任务。
- UI 回归：Prompt 流式长会话、任务列表大量历史、视频详情、媒体下载/导出、Android 持续监控。
- 性能验收：真机记录 JS 帧耗时、SQLite 写入次数、Provider 请求次数、下载并发、CPU/内存/温度趋势；长时间运行后按钮反馈和刷新延迟不得随历史数量线性恶化。

## 分阶段实施

1. 先增加失败测试和接口，不改变现有业务路径。
2. 实现数据库单例与异步 Repository，迁移详情页和列表读取。
3. 拆分状态同步与媒体队列，加入差异写入和退避。
4. 接入统一调度租约和 Android 任务 ID 过滤。
5. 实现 Prompt 快照合并、历史分页和流式 flush 合并。
6. 最后做列表行级渲染优化、真机性能采样和回归验证。
